# 小窗 XIAOCHUANG - 版本规划

**当前产品版本**: `0.23.1`
**上一版本**: `0.22.0`
**下一版本**: `0.23.2`
**最后更新**: 2026-07-07
**维护规则**: 每次规划、封版、改版本号时，先更新本文，再同步 GitHub 可见的 `RELEASES/` 与 `docs/` 中的版本事实源和版本索引。

## 1. 版本口径

小窗当前产品版本统一使用 `0.21.0` 及以上 SemVer 口径。

历史文档中的 `v1.x`、`v2.0`、`v2.2` 只作为历史阶段代号保留，不再作为当前排期口径。当前排期只看这条线：

| 版本 | 定位 | 状态 | 重点 |
|------|------|------|------|
| `0.21.0` | 核心创作闭环产品基线 | 已封版 | 前后端边界、后端真相源、任务/存储/AI Runtime、短剧/小说/画布/资产/设置主入口 |
| `0.21.1` | 稳定性与文档同步 patch | 已封版 | 创建入口口径、短剧长任务恢复、工作台视觉响应式、Settings Skill 校验 |
| `0.22.0` | 验收与产品逻辑收口版 | 已发布 | 完整验收记录、首页/短剧产品逻辑、小说源稿到方案草稿、AI 调用顺畅度与错误可解释性 |
| `0.23.0` | 0.23 规划包与文档列车入口 | 已规划 | 文档归档、需求入口收敛、短剧 AI-first 与画布闭环重新排期 |
| `0.23.1` | 短剧 AI-first 主流程修正版 | 当前版本 | 移除“方案草稿”主流程对象，建立源稿理解、改编策略、真实分集蓝图、项目资产引用的最小闭环 |
| `0.23.2` | 画布可信闭环验收版 | 下一版本 | 画布产物真实入资产、上传闭环、生成历史、来源追溯和基础快速生成验收 |
| `0.23.3` | 画布 AI 对话与镜头体验增强版 | 后续规划 | 画布 Skill 对话代理、角色/场景端口连线、合成导出节点和镜头主线体验 |
| `0.24.0` | 画布 Skill 扩展与协作准备 | 后续规划 | 删除节点、建立/删除连线、运行编排体验增强 |
| `0.25.0` | 画布生成与资产回用深化 | 后续规划 | 触发生成、保存资产 Skill、资产反向回用、更多运行历史 |
| `1.0.0-beta` | 对外试用候选版 | 远期目标 | 主要链路稳定、文档与验收完整、已知风险可控 |

## 2. 当前版本 `0.23.1`

`0.23.1` 是短剧 AI-first 主流程修正版。

本版本的目标是把短剧项目从“规则方案草稿预览”改为“真实 AI 产物逐步生成”的生产链：源稿理解、改编策略、分集蓝图、试播正文和单集工作台生产。

### 2.1 主要内容

| 方向 | 主要内容 | 价值 |
|------|----------|------|
| 短剧详情 | 主流程切换为 AI-first 状态面板，展示源稿健康、源稿理解、改编策略、分集蓝图和试播正文 | 用户看到的每一步都是可追踪的真实产物 |
| 方案草稿 | 旧方案草稿只作为兼容提示保留，不再作为主流程对象 | 解决“看似 AI 改编，实际是规则草稿”的产品错位 |
| 分集蓝图 | AI 基于已选策略创建真实 `Episode(status=blueprint)` | `Episode` 尽早成为生产主对象 |
| 试播正文 | 支持批量生成试播正文，也支持单集生成、重写和蓝图再生成 | 让用户能快速验证改编质量 |
| 长篇源稿 | 健康检查估算 token 与分块模式，超过上下文上限时走分块理解 | 避免长小说静默截断 |
| AI Runtime | 通过已配置文本 API 执行结构化生成，不新增独立远程 Agent 服务 | 复用现有配置，降低接入复杂度 |

### 2.2 与上一版 `0.22.0` 的差异

| 模块 | `0.22.0` | `0.23.1` |
|------|----------|----------|
| 版本目标 | 验收与产品逻辑收口 | 短剧 AI-first 主流程修正 |
| 短剧详情 | 小说源稿、方案草稿、目标设定、分集生成前置规划 | 源稿理解、改编策略、真实分集蓝图、试播正文 |
| 分集对象 | 可从方案草稿批量生成分集初稿 | AI 直接写入真实 `Episode` 蓝图 |
| AI Runtime | 明确哪些步骤真正调用 AI | 短剧主流程通过已配置文本 API 生成结构化产物 |
| 长篇源稿 | 有基础健康检查 | 估算上下文风险并支持分块理解 |
| 工作台输入 | 以脚本和媒体生产为主 | 读取蓝图与脚本，支持蓝图/脚本再生成 |

### 2.3 已知风险

| 风险 | 等级 | 说明 | 处理版本 |
|------|------|------|----------|
| 外部服务商下载本地媒体 URL 失败 | Medium | 本地 `127.0.0.1/static` 在真实云端模型侧不可访问时，图生视频参考图会失败 | `0.22.x` 先提示清楚，`0.23.2` 结合对象存储闭环强化 |
| 模型输出结构仍可能漂移 | Medium | 0.23.1 已增加常见字段别名归一化，仍需要沉淀失败样本回归 | `0.23.2` |
| 画布资产闭环仍未完全实证 | Medium | 画布上传、保存到资产、资产回源已有部分实现，但完整验收后移到短剧主流程之后 | `0.23.2` |
| 版本文档多入口历史包袱 | Low | 已将版本规划统一迁入 `docs/VERSION_PLAN.md` | `0.22.0` 已处理 |

## 3. 下一版本 `0.23.2`

`0.23` 拆成一条小版本列车推进，避免把短剧主流程重构和画布生产闭环塞进同一个大版本。

`0.23.2` 是下一交付版本，聚焦画布可信闭环与 0.23.1 AI-first 失败样本回归。短剧主流程已经进入真实 AI 产物链后，下一步要补齐资产、画布、上传、生成历史和长篇分块质量的可验收闭环。

### 3.1 目标

`0.23.2` 的目标：

- 画布产物真实写入资产库，并可在资产库预览、下载和打开来源画布。
- 上传图片、视频、音频真实进入画布，并可选择是否保存为资产。
- 节点生成历史可见、可切换、可下载、可保存资产。
- 短剧 AI-first 补充长篇分块质量样本和模型输出结构漂移回归。
- 保持画布 AI 对话代理和镜头主线体验后移到 `0.23.3`。

### 3.2 必做范围

| 优先级 | 范围 | 说明 |
|--------|------|------|
| P0 | 画布产物入资产 | 生成结果真实写入资产库，保留来源画布、节点和运行记录 |
| P1 | 上传闭环 | 图片、视频、音频上传进入画布，支持可选保存资产 |
| P2 | 生成历史 | 节点历史可见、可切换、可下载、可保存资产 |
| P3 | 资产回源 | 资产库可回到来源画布并定位相关节点 |
| P4 | AI-first 回归 | 补充长篇分块、模型字段漂移、真实 API 失败样本回归 |
| P5 | 最小快速生成 | 空白提示词或单节点快速生成结果插入为可见节点 |

### 3.3 不做范围

- 不做多人实时协作。
- 不做复杂分支版本合并。
- 不做完整时间线剪辑工具。
- 不在 `0.23.2` 做画布 Skill 对话代理、角色/场景端口连线或合成导出节点；画布 Agent 与镜头体验进入 `0.23.3`。
- 不做完整 8 个 Skill，全量 Skill 分到 `0.24.0` / `0.25.0`。
- 不新增独立原型页或复杂资产版本合并页。

### 3.4 0.23 小版本路径

| 版本 | 定位 | 优先级 | 主要交付 |
|------|------|--------|----------|
| `0.23.1` | 短剧 AI-first 主流程修正版 | 最高 | 源稿理解、改编策略、真实分集蓝图、项目资产引用、单集工作台输入升级 |
| `0.23.2` | 画布可信闭环验收版 | 高 | 资产闭环、上传闭环、节点生成历史、来源追溯、最小快速生成验收 |
| `0.23.3` | 画布 AI 对话与镜头体验增强版 | 中 | `create_nodes/update_node/add_to_context`、角色/场景端口、合成导出节点、镜头主线体验 |
| `0.24.0` | 画布 Skill 扩展 | 后续 | 删除节点、建立/删除连线、对话操作编排 |
| `0.25.0` | 画布生成与资产回用深化 | 后续 | 对话触发生成、保存资产 Skill、资产反向回用、更多运行历史 |

### 3.5 0.23.3 工程债偿还

`0.23.2` 体检（见 [系统体检报告-0.23.2-2026-07-08](./系统体检报告-0.23.2-2026-07-08.md) 与 [应对路线图-0.23.2-2026-07-08](./应对路线图-0.23.2-2026-07-08.md)）发现的安全与正确性硬伤已作为 `0.23.2-post` hotfix 立即处理；以下工程债进入 `0.23.3` 版本列车，与画布 AI 对话主线同期偿还：

| 编号 | 债项 | 范围 | 验收要点 |
|------|------|------|----------|
| M2-1 | OpenAPI 响应 schema 补全（契约债·核心） | 分模块：admin→canvas→auth→dramas→media→shared.ts 清理 | 后端 controller 补 `@ApiOkResponse`，`openapi.json` 响应 schema 覆盖率 ≥80%，web/admin 至少一模块改用 `generated.ts` 类型 |
| M2-2 | 版本基线一次性对齐 | Node 22、TS 6.0.2、Next 统一、package.json version 跟发版、补 root engines | 全仓 `@types/node`/`typescript`/`next` 同版本，release-gates 加 version 一致性校验 |
| M2-3 | 状态字段加 DB 级约束 | `tasks/canvas/dramas` 状态字段 `checkConstraint` 或 `pgEnum` | 误写非法状态被 DB 拒绝，迁移可回滚 |
| M2-4 | canvas 子表 FK 补全 | `canvasEdges`/`canvasTasks`/`canvasVersionNodes` 节点引用 `.references()` | 删除节点时关联 edges/tasks 同步清理，迁移前清洗孤儿数据 |
| M2-5 | 迁移可回滚机制 | 补 down 迁移或引入 node-pg-migrate、清理游离 `canvas_tables.sql`、补 meta snapshot | 关键迁移可回滚验证，snapshot 与迁移对齐 |
| M2-6 | CI 覆盖度补齐 | 加 `verify:v2-boundaries`、canvas e2e 进 CI、admin 补 typecheck | CI 跑边界检查 + canvas e2e，admin 独立 typecheck |
| M2-7 | Vidu webhook secret 改 header 传递 | `videos.webhook.ts` callback URL 不含 secret | secret 经 `x-vidu-webhook-secret` header 传递 |
| M2-8 | `packages/ui` 处置 | 实质填充或删除 | 不再编译空包，或至少一组件跨 web/admin 复用 |
| M2-9 | `drama/[id]` 巨型文件拆分 | 拆 `useDramaAiFirst` hook + 子组件、`generateCover` 加 AbortController | 主文件 <800 行，卸载即停轮询 |
| M2-10 | 前台鉴权一致性 | `drama/[id]` 纳入 server 守卫、清理 `/create` 死路由 | cookie 过期访问 `/drama/:id` 被重定向登录 |
| M2-11 | MSW 边界可视性 | mock 启用时显示 "Mock" 徽章、启动期 loading、清理 public 临时素材 | mock 模式有可视标识，启动无白屏 |
| M2-12 | i18n 落实或移除 | 落实 `t()` 消费或移除 `messages/en.json` 避免假承诺 | 切换语言界面变化，或无 i18n 残留误导 |
| M2-13 | `aiServiceConfigs` 索引 + 默认值唯一约束 | `(serviceType, isActive)` 索引 + `(userId, serviceType) WHERE isDefault` 部分唯一索引 | 查询走索引，同用户同类型至多一个 default |

> `0.23.2-post` hotfix 已处理（不进 0.23.3 列车）：uploads 匿名上传加守卫、canvas 节点结果 IDOR 加 ownership、视频任务锁 TTL 提到 15 分钟 + `refreshTaskLock` 加 `WHERE lockedBy`、Vidu webhook 重复处理改 CAS、`canvas_runs` 部分唯一索引兜底 triggerRun 竞态。`0.23.3` 内继续完成画布并发加固专题：triggerRun 事务化、save/backfill advisory lock、finalizeRun CAS、`reloadCanvas` 字段级 merge（详见路线图 M1）。

## 4. 发布纪律

每个版本必须维护这些内容：

1. 当前版本号、上一版本、下一版本。
2. 版本定位：为什么做这个版本。
3. 必做范围：做到什么算完成。
4. 不做范围：明确避免范围漂移。
5. 验收门禁：至少包含构建、类型、lint 或 E2E/烟测证据。
6. 已知风险：哪些问题接受带着走，进入哪个版本处理。
7. 更新日志：记录日期和变化。
