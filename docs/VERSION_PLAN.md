# 小窗 XIAOCHUANG - 版本规划

**当前产品版本**: `0.23.2`
**上一版本**: `0.23.1`
**下一版本**: `0.24.0`
**最后更新**: 2026-07-09
**维护规则**: 每次规划、封版、改版本号时，先更新本文，再同步 GitHub 可见的 `RELEASES/` 与 `docs/` 中的版本事实源和版本索引。

## 1. 版本口径

小窗当前产品版本统一使用 `0.21.0` 及以上 SemVer 口径。

历史文档中的 `v1.x`、`v2.0`、`v2.2` 只作为历史阶段代号保留，不再作为当前排期口径。当前排期只看这条线：

| 版本 | 定位 | 状态 | 重点 |
|------|------|------|------|
| `0.21.0` | 核心创作闭环产品基线 | 已封版 | 前后端边界、后端真相源、任务/存储/AI Runtime、短剧/小说/画布/资产/设置主入口 |
| `0.21.1` | 稳定性与文档同步 patch | 已封版 | 创建入口口径、短剧长任务恢复、工作台视觉响应式、Settings Skill 校验 |
| `0.22.0` | 验收与产品逻辑收口版 | 已发布 | 完整验收记录、首页/短剧产品逻辑、小说源稿到方案草稿、AI 调用顺畅度与错误可解释性 |
| `0.23.0` | 0.23 规划包与文档列车入口 | 已规划 | 文档归档、需求入口收敛、短剧 AI-first 与画布闭环重新排期 |
| `0.23.1` | 短剧 AI-first 主流程修正版 | 已封版 | 移除“方案草稿”主流程对象，建立源稿理解、改编策略、真实分集蓝图、项目资产引用的最小闭环 |
| `0.23.2` | 画布可信闭环验收版 | 当前版本，已封版 | 画布产物真实入资产、上传闭环、生成历史、来源追溯和基础快速生成验收 |
| `0.23.3` | 画布 AI 对话与镜头体验增强版 | 暂缓独立排期 | 原计划的画布 Skill、角色/场景端口、合成导出节点能力，按短剧项目中枢需要并入 `0.24.0` 或后续版本 |
| `0.24.0` | 短剧项目中枢升级版 | 下一版本 | `/drama/[id]` 全屏二级项目工作台、向导式剧集/剧本主线、短剧画布、素材池、镜头生产、导演助手、默认设置、项目内任务与导出 |
| `0.25.0` | 画布生成与资产回用深化 | 后续规划 | 触发生成、保存资产 Skill、资产反向回用、更多运行历史 |
| `1.0.0-beta` | 对外试用候选版 | 远期目标 | 主要链路稳定、文档与验收完整、已知风险可控 |

## 2. 当前版本 `0.23.2`

`0.23.2` 是画布可信闭环验收版，已完成封版。封版证据见 [0.23/0.23.2封版说明.md](./0.23/0.23.2封版说明.md)。

本版本不是大范围新增功能版本，而是把 `0.23.1` 期间已落地的画布能力补成可信闭环：节点生成历史并发写保护、画布资产来源口径、上传入资产、历史切换、快速生成和刷新不丢均已进入封版验收。

### 2.1 主要内容

| 方向 | 主要内容 | 价值 |
|------|----------|------|
| 节点生成历史 | `appendResult / selectResult / markAssetId` 进入事务并锁定目标节点行 | 并发生成不丢历史结果 |
| 资产闭环 | 收敛 `canvas_upload / canvas_generation / canvas_export / canvas_history` 来源类型，支持资产库展示、筛选和回源 | 画布产物可沉淀、可追溯、可复用 |
| 上传闭环 | 图片 30MB、视频 200MB、音频 100MB 分档限制与失败文案验收 | 上传节点和入资产行为可预测 |
| 生成历史 | 历史追加、20 条截断、切换当前结果、下载、保存资产和刷新保持均有测试证据 | 用户可以放心多次生成和回看 |
| 最小快速生成 | 空白右键和单节点右键快速生成结果进入节点历史，不自动进资产 | 快速试错不污染资产库 |
| 封版证据 | 后端 Canvas 单测、后端 typecheck、Web typecheck、Canvas E2E 均通过 | 版本完成标准可复查 |

### 2.2 与上一版 `0.23.1` 的差异

| 模块 | `0.23.1` | `0.23.2` |
|------|----------|----------|
| 版本目标 | 短剧 AI-first 主流程修正 | 画布可信闭环验收 |
| 主线对象 | 源稿理解、改编策略、分集蓝图、试播正文 | 画布节点结果、资产、上传、历史和来源追溯 |
| 资产闭环 | 画布能力已有雏形，未作为主线验收 | 画布结果可入资产、筛选、预览/下载、打开来源画布 |
| 生成历史 | 已有前后端基础能力，缺并发写保护和专项测试 | 补事务/锁、后端单测和 Canvas E2E |
| 快速生成 | 已有最小链路 | 明确默认进入历史、不自动进入资产，并完成 E2E |
| 封版证据 | 短剧 AI-first 真实 API 验证 | Canvas 后端单测、类型检查和 E2E 通过 |

### 2.3 已知风险

| 风险 | 等级 | 说明 | 处理版本 |
|------|------|------|----------|
| `source_type` 尚无 DB 级枚举约束 | Low | `0.23.2` 完成应用层常量收敛；数据库约束可后续评估 | `0.24.0+` |
| AI-first 失败样本回归未纳入封版阻塞 | Medium | 长篇分块、字段漂移、真实 API 失败样本在 0.23.2 规格中为可选项 | 后续专项 |

| 版本文档多入口历史包袱 | Low | 已将版本规划统一迁入 `docs/VERSION_PLAN.md` | `0.22.0` 已处理 |

## 3. 下一版本 `0.24.0`

`0.24.0` 定位为短剧项目中枢升级版。这个版本不再按 `0.23.x` 的小增强处理，而是围绕短剧项目生产方式做一次较大升级。

核心判断：

- `/drama/[id]` 应升级为 `(studio)` 全屏二级项目工作台，而不是普通详情页。
- 现有小说、通用画布、全局资产库、任务中心继续独立存在。
- 剧集/剧本的向导式 AI-first 流程是确定性主线；画布是可选增强，不是生产必经路径。
- 短剧模块内部可以拥有自己的短剧画布，不必与外部通用画布完全一致。
- 底层复用 Canvas、Assets、Tasks、Images、Videos、Audio、Storage、AI Config 等基础能力。
- 产品体验对标 DramaClaw 项目模块，形成短剧项目内部的画布、素材池、镜头生产、导演助手等项目级能力。

详细方案见 [0.24.0/README.md](./0.24.0/README.md)。

### 3.1 目标

`0.24.0` 的目标：

- 将 `/drama/[id]` 改造为 `(studio)` 全屏二级短剧项目工作台。
- 拆解旧 `(default)/drama/[id]/page.tsx`，迁移并回归 0.23 AI-first 主流程。
- 新增项目内导航与总览。
- 保留向导式剧集/剧本主线，用户不创建画布也能推进源稿理解、分集、正文、分镜和镜头生产。
- 新增短剧画布：面向短剧生产链路的项目内画布。
- 新增素材池：项目级素材候选池、主线资产和镜头私有资产管理。
- 新增镜头生产：按镜头组织首帧、尾帧、配音、视频、状态和批量生成。
- 新增导演助手：项目体检、缺口识别、生产建议和跳转动作。
- 新增默认设置、项目内任务和导出视角。

### 3.2 必做范围

| 优先级 | 范围 | 状态 | 说明 |
|--------|------|------|------|
| P0a | 项目壳与总览 | 待推进 | `(studio)/drama/[id]` 全屏二级工作台、项目顶栏、项目内导航、项目健康摘要 |
| P0b | 旧详情页拆解回归 | 待推进 | 拆解旧 4000 行级详情页，迁移单集、分镜和 AI-first 主流程能力 |
| P1 | 短剧画布 | 待推进 | `canvases.profile = drama`、从单集投射画布、来源分镜定位、画布同步 |
| P2 | 素材池 | 待推进 | `drama_asset_links`、候选资产、主线资产、提交回填、来源追踪 |
| P3 | 镜头生产 | 待推进 | 镜头生产列表、缺失筛选、批量预览、批量生成、状态回填 |
| P4 | 导演助手 | 待推进 | 项目体检、缺口列表、建议卡片、跳转和部分可执行建议 |

### 3.3 不做范围

- 不重写现有通用画布。
- 不把外部通用画布强行并入短剧模块。
- 不重写现有资产库。
- 不新增第二套任务队列。
- 不新增第二套模型 Provider。
- 不实现完整自治 Agent。
- 不实现复杂 3D/360/Director World。
- 不做多人实时协同。

## 4. 发布纪律

每个版本必须维护这些内容：

1. 当前版本号、上一版本、下一版本。
2. 版本定位：为什么做这个版本。
3. 必做范围：做到什么算完成。
4. 不做范围：明确避免范围漂移。
5. 验收门禁：至少包含构建、类型、lint 或 E2E/烟测证据。
6. 已知风险：哪些问题接受带着走，进入哪个版本处理。
7. 更新日志：记录日期和变化。
