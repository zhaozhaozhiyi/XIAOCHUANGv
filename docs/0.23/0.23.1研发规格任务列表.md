# 0.23.1 研发规格任务列表

版本：`0.23.1`
日期：`2026-07-06`
状态：研发规格冻结补充稿
主线：短剧 AI-first 主流程修正版

## 1. 版本目标

`0.23.1` 只解决一个主问题：把短剧项目从“小说源稿 -> 方案草稿 -> 分集制作”的伪规划链路，改成“源稿理解 -> 改编策略 -> 真实分集蓝图 -> 试播正文 -> 单集工作台”的真实 AI 产物链。

封版成功标准：

1. 项目详情主流程不再展示“方案草稿”主面板。
2. 源稿导入后能看到健康检查与 AI 源稿理解。
3. 用户能生成、比较并选择至少 2 套 AI 改编策略。
4. 系统能基于选定策略创建真实 `Episode(status=blueprint)`。
5. 至少 1 集能从 blueprint 生成试播正文并进入单集工作台。
6. 单集工作台能区分项目公共主档、单集引用/覆写、镜头私有产物。
7. 旧 `adaptationPlan` 项目不崩溃，有兼容或迁移路径。
8. 长篇源稿不得静默截断；超过模型上下文时必须走分块理解或远程 Agent 执行链路。

## 2. 不做范围

- 不做完整画布 Agent。
- 不做画布角色/场景端口连线。
- 不做画布合成导出节点收口。
- 不做完整资产版本系统。
- 不做独立角色圣经页或独立场景圣经页。
- 不强制独立 `/drama/[id]/strategy` 页面，但策略生成、比较、选择能力必须做。
- 不强制独立 `/drama/[id]/settings` 页面。
- 不一次性迁移完全部历史 `adaptationPlan` 数据。

## 3. 领域数据规格

### 3.1 `source_health`

用途：源稿结构化健康检查，先判断“能不能直接改”。

最小字段：

- `status`: `ok | warning | blocked`
- `word_count`
- `chapter_count`
- `estimated_tokens`
- `over_context_limit`
- `chunk_count`
- `recommended_mode`: `direct | long_source | long_source_async`
- `chapter_index[]`: `chapter_no / title / word_count / brief`
- `anomalies[]`: `type / severity / message / evidence`
- `named_entity_density`
- `continuity_score`
- `generated_at`

### 3.2 `source_analysis`

用途：AI 对源稿做改编理解。

最小字段：

- `theme`
- `core_conflict`
- `protagonist`
- `antagonist`
- `protagonist_goal`
- `relationship_map[]`
- `world_rules[]`
- `emotional_curve[]`
- `adaptation_risks[]`
- `evidence[]`: 每条结论可追溯章节或片段。
- `ai_run_id`
- `generated_at`

### 3.3 `adaptation_brief`

用途：AI 给出的可比较改编策略。

最小字段：

- `id`
- `name`
- `claim`
- `rhythm_model`
- `target_episode_count`
- `episode_duration`
- `style_direction`
- `hook_density`
- `retained_points[]`
- `removed_points[]`
- `risk_notes[]`
- `production_cost`
- `recommended_for`
- `ai_run_id`
- `generated_at`

### 3.4 `episode.blueprint_payload`

用途：真实分集蓝图，是后续正文、工作台、资产引用的输入。

最小字段：

- `episode_number`
- `title`
- `positioning`
- `opening_hook`
- `summary`
- `source_trace[]`
- `characters[]`
- `scenes[]`
- `ending_hook`
- `risk_notes[]`
- `brief_id`
- `ai_run_id`
- `generated_at`

### 3.5 状态机

Drama 状态：

- `source_pending`
- `source_ready`
- `brief_pending`
- `brief_selected`
- `blueprint_generating`
- `blueprint_ready`
- `script_generating`
- `in_production`
- `deliverable_ready`

Episode 状态：

- `blueprint`
- `script_generating`
- `script_ready`
- `storyboard_ready`
- `asset_ready`
- `composed`
- `failed`

兼容规则：

- 旧 `draft` episode 可视为 `script_ready` 或 `legacy_draft`，由页面做兼容展示。
- 旧 `adaptationPlan` 不再展示为主流程对象，只可映射成兼容提示或一次性迁移入口。
- Drama 主业务 `status` 不直接替换为上述 AI-first 状态；0.23.1 新增或派生 `ai_first_stage` 作为短剧改编链路状态，避免破坏旧项目列表、筛选、发布和审核逻辑。

### 3.6 长篇源稿与远程 Agent 执行原则

长篇源稿规则：

- 源稿全文永远落库，不因为模型上下文限制截断。
- 健康检查必须估算 token，并输出 `estimated_tokens / over_context_limit / chunk_count / recommended_mode`。
- 当 `over_context_limit = true` 时，必须进入 `long_source` 模式。
- `long_source` 模式下，AI 只读取分块、摘要、章节索引和相关片段，不直接读取整本全文。

长篇源稿持久化规则：

- 0.23.1 必须新增可恢复的 source chunk 存储，不允许只把 chunk 放在前端内存或一次性请求上下文中。
- 推荐新增 `drama_sources` 与 `drama_source_chunks`；若研发容量不足，至少要在后端持久化 `metadata.ai_first.source_chunks`，但不得影响 `dramas.metadata` 的可读性和查询性能。
- chunk 级处理必须能单独重试、单独标记失败、单独追溯远程 Agent run。

`drama_sources` 建议字段：

- `id`
- `user_id`
- `drama_id`
- `source_type`: `paste | upload | writing_project`
- `title`
- `content_hash`
- `content_storage_ref` 或 `content`
- `word_count`
- `estimated_tokens`
- `chapter_count`
- `status`
- `created_at`
- `updated_at`

`drama_source_chunks` 建议字段：

- `id`
- `user_id`
- `drama_id`
- `source_id`
- `chunk_no`
- `chapter_no`
- `title`
- `content_start`
- `content_end`
- `content_hash`
- `estimated_tokens`
- `summary_payload`
- `extraction_payload`
- `source_trace`
- `status`: `pending | running | ready | failed`
- `ai_run_id`
- `remote_run_id`
- `failure_reason`
- `created_at`
- `updated_at`

远程 Agent 原则：

- 远程 Agent 可以作为推理和生成引擎。
- 本地后端仍是权限、状态、任务、幂等、失败、成本、数据落库和源文追溯的真相源。
- 前端不得直接调用远程 Agent。
- 远程 Agent 不得自行决定写库结构，不得绕过后端状态机。
- 远程 Agent 输出必须经过 JSON schema 校验后才能落库。

推荐调用链：

`前端 -> 后端 API -> AI Runtime / DramaAgentService -> RemoteDramaAgentAdapter -> 远程 Agent -> 结构化结果校验 -> 本地数据库`

## 4. 研发任务清单

### R231-00 版本范围与开关

优先级：P0

目标：保证 0.23.1 主线不会被画布和后续 Skill 范围污染。

任务：

1. 增加短剧 AI-first 内部能力开关，建议名为 `drama_ai_first_enabled`。
2. 旧项目在开关关闭时仍走旧路径；开关开启时走新主链。
3. 画布相关 0.23.2/0.23.3 入口不进入 0.23.1 主导航变更。
4. “全站移除方案草稿”仅约束 AI-first 新主流程；旧路径或兼容提示中允许出现“旧方案草稿”。

验收：

- 开关打开后，短剧详情不展示“方案草稿”主面板。
- 开关关闭或旧数据异常时，不影响已有项目打开。
- 开关关闭时，旧路径文案不纳入 0.23.1 AI-first 文案验收。

### R231-01 类型与契约定义

优先级：P0

目标：先统一前后端数据结构，避免页面和 API 各写一套自由 JSON。

任务：

1. 在 contracts 或共享类型中新增 `SourceHealth / SourceAnalysis / AdaptationBrief / EpisodeBlueprintPayload`。
2. 扩展 `Drama` 返回结构，能返回 `source_health / source_analysis / adaptation_briefs / selected_brief_id`。
3. 扩展 `Episode` 返回结构，能返回 `blueprint_payload / source_trace / generation_mode / failure_reason`。
4. 前端新增解析工具，兼容旧 `metadata.adaptation_plan` 和新 AI-first 字段。

验收：

- TypeScript 类型不使用 `any` 透传核心 AI-first 结构。
- 旧项目、无源稿项目、新 AI-first 项目都能被解析。

### R231-02 数据库最小迁移

优先级：P0

目标：让 AI-first 关键产物可落库、可刷新恢复、可追溯。

建议实现：

1. `episodes` 新增：
   - `blueprint_payload` text/jsonb nullable
   - `source_trace` text/jsonb nullable
   - `generation_mode` varchar nullable
   - `failure_reason` text nullable
2. 新增或规划源稿持久化结构：
   - 首选：`drama_sources` / `drama_source_chunks`
   - 兼容：短篇仍可从现有 `metadata.novel_source` 读取
   - 禁止：长篇只保存在单次请求上下文中
3. `dramas.metadata` 继续承载 0.23.1 的 `ai_first` 聚合状态，不承载不可控增长的大体量 chunk 正文：
   - `source_health`
   - `source_analysis`
   - `adaptation_briefs`
   - `selected_brief_id`
   - `ai_first_stage`
   - `ai_first_updated_at`
4. 多写操作必须包 transaction：
   - 保存源稿 + health
   - 生成 source chunks + 更新 health
   - 更新 chunk 摘要 + 合并 source_analysis
   - 生成 briefs + 更新状态
   - 选中 brief + 更新状态
   - 创建 episode blueprints + 更新 drama 状态和 totalEpisodes

后续可演进：

- 若 `source_analysis` 或 `adaptation_brief` 需要版本历史，再拆独立表；0.23.1 不强制。

验收：

- 刷新页面后 source、brief、blueprint 不丢失。
- 长篇 source chunks 刷新后可恢复处理进度。
- 生成蓝图中途失败不会留下半套不可解释数据。
- 旧 `episodes` 查询不因新增字段破坏。

### R231-03 源稿导入与健康检查 API

优先级：P0

建议接口：

- `GET /api/v1/dramas/:id/ai-first`
- `POST /api/v1/dramas/:id/source`
- `POST /api/v1/dramas/:id/source/health-check`

任务：

1. 复用现有 `novel_source` 保存逻辑，但输出新 `source_health`。
2. 健康检查先做确定性规则：
   - 空正文
   - API envelope
   - HTML 页面
   - 字数过短
   - 章节识别异常
   - 重复段落
3. 生成 `chapter_index`。
4. 如果 `over_context_limit = true`，生成并持久化 `source_chunks`。
5. 更新 `ai_first_stage`：
   - 无源稿：`source_pending`
   - 可用：`source_ready`
   - 阻塞：保持 `source_pending` 并返回 blocked health。

验收：

- 粘贴有效正文后能得到 `ok` health。
- 粘贴 API JSON 或 HTML 时返回 blocked，页面不能继续生成策略。
- 重新导入源稿会标记旧 brief/blueprint 需要重生。
- 超上下文源稿会生成可恢复的 chunk 列表，而不是在 AI 请求时临时切块。

### R231-04 AI 源稿理解

优先级：P0

建议接口：

- `POST /api/v1/dramas/:id/source/analyze`

任务：

1. 新增 AI skill 或 service：`drama_source_analyzer`。
2. 输入：`novel_source 或 source_chunks + source_health + target constraints`。
3. 输出严格 JSON：`source_analysis`。
4. 记录 `ai_run_id` 和错误原因。
5. 支持重跑，重跑后保留最新结果即可；0.23.1 不做版本历史。
6. 当 `source_health.over_context_limit = true` 时，必须通过分块理解或 `RemoteDramaAgentAdapter` 执行，不允许截断全文后生成。

验收：

- 有效源稿可生成核心冲突、主角目标、关系、风险。
- AI 失败时页面显示可重试和失败原因。
- source_analysis 中的关键结论至少有章节或片段证据。
- 长篇源稿会显示分块/远程 Agent 处理进度，不会静默丢弃后文。

### R231-04A 远程 Drama Agent Adapter

优先级：P0

目标：为长篇源稿理解、策略生成、蓝图生成和试播正文生成提供统一远程 Agent 执行层，同时保持本地系统是真相源。

启用策略：

- 远程 Agent Adapter 是 AI 执行层的统一适配能力。
- 长篇源稿 `recommended_mode = long_source | long_source_async` 时必须启用远程 Agent 或等价分块执行器。
- 短篇源稿可走本地 AI Runtime，也可按配置走远程 Agent。
- 无论使用哪种执行器，落库、状态推进、幂等和 schema 校验都只能由本地 service 完成。

建议模块：

- `DramaAgentService`
- `RemoteDramaAgentAdapter`
- `DramaAgentTask`
- `DramaAgentSchemaValidator`

配置建议：

- `DRAMA_AI_FIRST_ENABLED`
- `DRAMA_AI_FIRST_LOCAL_RULE_FALLBACK`：仅限内部联调/测试；生产环境必须关闭，不能作为封版验收产物来源。
- `DRAMA_AGENT_PROVIDER`
- `DRAMA_AGENT_BASE_URL`
- `DRAMA_AGENT_API_KEY`
- `DRAMA_AGENT_MAX_RETRIES`
- `DRAMA_AGENT_MAX_CHUNK_TOKENS`

远程模型调用不设置应用层 `timeout` 或 `max_tokens`，由已选模型服务决定单次输出长度与响应时长；本地任务系统只负责取消、持久化、重试和状态展示。

支持任务类型：

- `source_chunk_analyze`
- `source_global_summarize`
- `adaptation_brief_generate`
- `episode_blueprint_generate`
- `episode_script_generate`
- `asset_match_suggest`

输入规范：

- `task_type`
- `drama_id`
- `user_id`
- `source_chunk_ids` 或 `source_trace`
- `selected_brief_id`
- `episode_id`
- `constraints`
- `output_schema`
- `idempotency_key`

输出规范：

- `status`: `succeeded | failed | partial`
- `result`
- `source_trace[]`
- `usage`
- `warnings[]`
- `error`
- `remote_run_id`

任务：

1. 后端封装远程 Agent 调用，不允许前端直连。
2. 所有远程 Agent 调用写入本地 AI run 或等价任务记录。
3. 调用前生成 `idempotency_key`，避免重试造成重复写入。
4. 调用后按任务类型做 JSON schema 校验。
5. 校验失败时不落库，记录失败原因和原始摘要。
6. 支持超时、重试、取消和局部失败。
7. 长篇源稿按章节或 token 分块提交，结果先落 chunk 级摘要，再合并为全局 `source_analysis`。
8. 远程 Agent 只能返回结构化建议，最终写库由本地 service 完成。
9. Adapter 必须先于 `drama_source_analyzer / drama_adaptation_brief_generator / drama_episode_blueprint_generator / drama_episode_script_generator` 的远程执行路径完成。

验收：

- 远程 Agent 不可用时，页面显示可解释失败，不破坏已有源稿和已生成产物。
- 同一个任务重试不会重复创建 brief 或 episode。
- 远程 Agent 返回非预期 JSON 时，不会污染数据库。
- 长篇源稿能通过 chunk 级处理生成全局 `source_analysis`。
- `adaptation_brief / episode.blueprint_payload / script_content` 都能追溯到本地 `ai_run_id` 和远程 `remote_run_id`。

### R231-05 改编策略生成与选择

优先级：P0

建议接口：

- `POST /api/v1/dramas/:id/adaptation-briefs`
- `POST /api/v1/dramas/:id/adaptation-briefs/:briefId/select`

任务：

1. 新增 AI skill 或 service：`drama_adaptation_brief_generator`，可通过 `DramaAgentService` 调用远程 Agent。
2. 一次生成 2 到 3 套策略。
3. 每套策略必须包含节奏模型、集数建议、风险、产能成本。
4. 用户必须显式选择一套策略后才能生成蓝图。
5. 选择 brief 后写入 `selected_brief_id`，drama 状态进入 `brief_selected`。

验收：

- 页面至少展示 2 套策略。
- 未选择策略时，生成蓝图按钮不可用。
- 重新生成策略会提示旧蓝图可能失效。

### R231-06 Episode Blueprint 生成

优先级：P0

建议接口：

- `POST /api/v1/dramas/:id/episode-blueprints`
- `PATCH /api/v1/episodes/:id/blueprint`
- `POST /api/v1/episodes/:id/regenerate-blueprint`

任务：

1. 新增 AI skill 或 service：`drama_episode_blueprint_generator`，可通过 `DramaAgentService` 调用远程 Agent。
2. 基于 `selected_brief + source_analysis + source_health.chapter_index` 生成全季蓝图。
3. 直接创建或更新真实 `Episode`，状态为 `blueprint`。
4. 每集写入 `blueprint_payload` 和 `source_trace`。
5. 保证幂等：
   - 无 episode 时创建。
   - 已有 blueprint 但无 script 时允许覆盖。
   - 已有 script 时默认禁止全量覆盖，只允许单集重生或用户确认覆盖。
6. 更新 `dramas.totalEpisodes` 和 drama 状态 `blueprint_ready`。

验收：

- 分集列表看到的全部是真实 episode。
- 每个 episode 至少有标题、定位、开场钩子、摘要、原文映射、角色、场景、结尾悬念、风险。
- 生成失败时可重试，不产生重复 episode。

### R231-07 试播正文生成

优先级：P0

建议接口：

- `POST /api/v1/dramas/:id/pilot-scripts`
- `POST /api/v1/episodes/:id/generate-script`
- `POST /api/v1/episodes/:id/rewrite-script`

任务：

1. 新增 AI skill 或 service：`drama_episode_script_generator`，可通过 `DramaAgentService` 调用远程 Agent。
2. 默认入口为“生成试播 1 到 3 集”。
3. 输入：`episode.blueprint_payload + selected_brief + source_trace`。
4. 输出写入：
   - `episode.content`: 可读正文或兼容正文
   - `episode.scriptContent`: 工作台使用正文
   - `episode.status = script_ready`
5. 批量生成时每集独立失败，允许只重跑失败集。
6. 多集试播正文必须接入可轮询任务，不允许只依赖前端按钮 loading。
7. 任务域固定为 `drama_pilot_scripts`，`domain_id = drama.id`，同一短剧同一时间最多一个活动试播正文任务。
8. `GET /api/v1/dramas/:id/ai-first` 必须返回 `pilot_script_task`，字段结构与 `source_analysis_task` 一致，用于刷新恢复和前端轮询。
9. 任务 payload 至少包含 `drama_id / episode_ids / episode_numbers / limit`；进度摘要至少包含 `phase / total_episodes / completed_episodes / failed_episodes / current_episode_number`。
10. 正式环境没有远程 Agent 或真实 AI Runtime 时，不得创建注定失败的试播任务，应直接返回可解释的 agent required 错误。

验收：

- 至少第 1 集能从 blueprint 生成正文。
- 正文生成后能进入现有单集工作台。
- 生成失败集显示 `failure_reason`，不阻塞已成功集。
- 页面刷新后仍能看到试播正文任务进度；完成后能自动刷新分集状态并进入目标分集工作台。
- 取消任务时，仍在 `script_generating` 的分集回退到 `blueprint`，已成功写入正文的分集不被覆盖。
- 重试任务时，不重复创建 episode，不覆盖已有 `script_ready` 正文。

## 5. 补充定论

### 5.1 P0 封版切片

0.23.1 的 P0 不再按“页面数量”拆，而按一条可跑通的真实产物链拆：

1. 源稿可保存、可恢复、可健康检查。
2. 长篇源稿可持久化分块，不发生静默截断。
3. 源稿理解能生成结构化 `source_analysis`。
4. 改编策略能生成至少 2 套 `adaptation_brief`，且用户必须显式选择。
5. 选中策略后能生成真实 `Episode(status=blueprint)`。
6. 至少第 1 集能由 blueprint 生成 `scriptContent`。
7. 单集工作台能读取 `blueprint_payload + scriptContent`，不依赖旧方案草稿。
8. 旧 `adaptationPlan` 项目能打开，并明确标记为旧数据。

P0 可延期项：

- 独立 `/strategy` 页面。
- 独立 `/assets` 页面完整资产治理。
- 角色、场景、镜头级完整版本快照。
- 全季正文一键生成的高级调度。
- 旧项目批量自动迁移。

P0 不可延期项：

- 不得继续把 `adaptationPlan` 当主流程完成态。
- 不得在长篇源稿上截断后伪装成全文理解。
- 不得只生成前端临时蓝图而不创建真实 episode。
- 不得让远程 Agent 直接写库或绕过本地状态机。

### 5.2 长篇源稿处理阈值

0.23.1 按估算 token 决定处理模式：

| 区间 | 推荐模式 | 处理要求 |
| --- | --- | --- |
| `0` | blocked | 缺源稿，不能继续 |
| `< 3,000` | warning | 可分析，但提示源稿过短 |
| `3,000 - 60,000` | direct | 可直接进入 AI 理解 |
| `60,000 - 400,000` | long_source | 必须分块，允许本地分块执行器或远程 Agent |
| `> 400,000` | long_source_async | 必须异步、可恢复、chunk 级重试 |

工程约束：

1. `60,000` 不是模型真实上限，而是产品安全阈值；具体模型可配置，但页面不暴露模型内部上下文。
2. 分块大小默认按 `DRAMA_AGENT_MAX_CHUNK_TOKENS` 控制，建议初始值 `12,000`。
3. 每个 chunk 必须有 `content_hash`，重跑时优先复用未变化 chunk 的摘要。
4. 全局 `source_analysis` 只能由 chunk 摘要、章节索引和必要原文片段合成，不能把全文重新塞回单次上下文。
5. 分块结果允许 `partial`，但 `partial` 只能展示为“部分理解完成”，不能进入策略生成。

### 5.3 远程 Agent 接入定论

可以接远程 Agent，但它只能是执行器，不能成为系统主控。

本地后端必须负责：

- 用户权限。
- 项目状态推进。
- 源稿与 chunk 持久化。
- 幂等键生成。
- JSON schema 校验。
- AI run / remote run 追溯。
- 成本、超时、重试、失败记录。
- 最终写库。

远程 Agent 只负责：

- 按任务输入做推理或生成。
- 返回结构化 JSON。
- 返回 `remote_run_id / usage / warnings / error`。

远程 Agent 禁止：

- 直接读写业务数据库。
- 自行创建 brief 或 episode。
- 直接修改 drama 状态。
- 直接被前端调用。
- 返回自由文本后由前端自行解析落库。

### 5.4 异步任务与幂等规则

下列动作必须按异步任务或可轮询任务处理：

- 长篇源稿 chunk 生成。
- 长篇源稿 chunk 分析。
- 全局 source_analysis 合成。
- adaptation_brief 生成。
- 全季 episode_blueprint 生成。
- 试播多集正文生成。

幂等键建议：

| 动作 | 幂等键 |
| --- | --- |
| source health | `drama:{id}:source:{content_hash}:health` |
| chunk analyze | `drama:{id}:source:{source_id}:chunk:{chunk_no}:{content_hash}:analyze` |
| source analysis | `drama:{id}:source:{source_id}:{content_hash}:analysis` |
| brief generate | `drama:{id}:analysis:{ai_run_id}:brief:{batch_no}` |
| blueprint generate | `drama:{id}:brief:{brief_id}:blueprint:{source_hash}` |
| script generate | `episode:{episode_id}:blueprint:{blueprint_hash}:script:{mode}` |

任务域建议：

| 动作 | `tasks.domain_table` | `tasks.domain_id` | 前端 payload 字段 |
| --- | --- | --- | --- |
| 长篇源稿理解 | `drama_sources` | `source.id` | `source_analysis_task` |
| 改编策略生成 | `drama_adaptation_briefs` | `drama.id` | `brief_task` |
| 全季分集蓝图生成 | `drama_episode_blueprints` | `drama.id` | `blueprint_task` |
| 试播多集正文生成 | `drama_pilot_scripts` | `drama.id` | `pilot_script_task` |

重复提交同一幂等键时：

- 任务已成功：返回已有结果。
- 任务运行中：返回当前任务状态。
- 任务失败：允许重试，但必须保留失败记录。

### 5.5 数据失效规则

重新导入源稿后，必须按影响范围标记旧产物：

| 变化 | source_analysis | adaptation_brief | episode blueprint | scriptContent |
| --- | --- | --- | --- | --- |
| 源稿正文 hash 改变 | 失效 | 失效 | 失效 | 保留但标记源稿已变更 |
| 只修改标题 | 保留 | 保留 | 保留 | 保留 |
| 重新生成 source_analysis | 更新 | 失效 | 失效 | 保留但标记理解已变更 |
| 重新生成 briefs | 保留 | 更新 | 失效 | 保留但标记策略已变更 |
| 重新选择 brief | 保留 | 保留 | 失效 | 保留但标记策略已变更 |
| 单集重生 blueprint | 保留 | 保留 | 单集更新 | 对应单集 script 失效 |

失效产物不能删除用户已经生成的正文和工作台资产，只能提示“来源已更新 / 理解已更新 / 策略已更新 / 蓝图已更新，建议重生”。删除或覆盖必须由用户确认。

实现口径：

- `episode.generation_mode` 可追加轻量失效后缀：`_source_stale`、`_analysis_stale`、`_strategy_stale`、`_blueprint_stale`。
- 为避免字段膨胀，只保留最新失效原因，不叠加多个 stale 后缀。
- 新蓝图或新正文生成成功后，应写回正式生成模式，清除旧 stale 后缀。

### 5.6 前端 UI 与交互一致性

0.23.1 的界面风格维持当前产品的苹果式克制风格，不做视觉大改版。

约束：

1. 使用现有 `content-kit`、按钮、卡片、状态色和间距体系。
2. 页面只保留一个主 CTA，其他动作降级为次按钮或菜单。
3. 状态条、进度、风险提示在列表页、概览页、分集页保持同一套阶段命名。
4. 不增加营销式 hero、夸张渐变、装饰性大图或大面积彩色卡片。
5. 主流程中的卡片只承载真实产物，不用卡片包装“功能说明”。
6. AI 运行中、失败、重试、部分完成、旧数据兼容都必须有明确状态，不用 toast 作为唯一反馈。
7. 长篇处理中必须展示 chunk 或阶段进度，不能只显示“AI 正在思考”。

### 5.7 封版 No-Go

出现以下任一情况，0.23.1 不允许封版：

1. 新项目仍以“方案草稿”为主流程对象。
2. 源稿超过上下文后仍能继续生成，但没有分块或远程 Agent 记录。
3. 策略生成只有 1 套，或用户未选择策略也能生成蓝图。
4. 蓝图只存在前端内存或 metadata 临时字段，没有真实 episode。
5. 正文生成失败后没有 `failure_reason`。
6. 远程 Agent 输出 schema 校验失败仍落库。
7. 旧项目打开白屏。
8. 列表页、详情页、工作台对同一项目显示不同阶段。
9. `local_rule_seed / local_rule_blueprint / local_rule_script` 仍被当作正式 AI 产物验收。

## 7. 交付判定

`0.23.1` 不按“完成多少页面”判定，而按真实主链判定：

这条链路只要断在任何一环，`0.23.1` 就不能封版。

## 8. 研发评审补充

### 8.1 规格可执行性结论

本研发规格可以作为 `0.23.1` 执行基线，但封版判断必须从“有没有接口和页面入口”升级为“有没有真实 AI 产物链”。也就是说，后端能保存 source、创建 brief、创建 blueprint episode，只能证明链路结构成立；只有源稿理解、策略、蓝图、正文都由真实 AI Runtime 或远程 Agent 生成，并且有 `ai_run_id / remote_run_id / source_trace / schema 校验 / failure_reason`，才算满足版本目标。

### 8.2 本地规则执行器的定位

研发允许先使用本地规则执行器打通数据、状态和 UI，但必须满足以下口径：

- `local_rule_seed` 只能算结构化种子，用于联调和测试。
- `local_rule_blueprint` 只能算蓝图占位，用于验证真实 Episode 创建、幂等和页面展示。
- `local_rule_script` 只能算试播正文占位，用于验证工作台输入。
- 三者都不能被产品文案包装成“AI 已完成”。
- 封版前必须替换为真实 AI Runtime 或 `RemoteDramaAgentAdapter` 输出，或者在能力开关中明确标记为内部演示模式。

### 8.3 当前研发优先级调整

如果已经完成类型、数据库、source 保存、brief 选择和 blueprint episode 创建，下一步优先级不再是继续拆更多页面，而是补齐下面 5 个封版缺口：

1. 接入 `RemoteDramaAgentAdapter` 或等价真实 AI Runtime，替换本地规则种子。
2. 把“生成试播 1 到 3 集”作为分集蓝图后的可见主 CTA 接入前端。
3. 单集工作台读取并展示 `blueprint_payload + scriptContent`，且提示公共资产、单集引用和镜头私有产物边界。
4. 长篇 `long_source_async` 进入可轮询任务，不只是在同步请求里生成 chunk。
5. 补 E2E：源稿、策略、蓝图、试播、工作台、旧 `adaptationPlan` 兼容。

### 8.4 补充验收口径

`0.23.1` 验收时按下面顺序看证据：

1. 数据证据：source、chunk、analysis、brief、selected brief、episode blueprint、script 都能刷新恢复。
2. 执行证据：每次 AI 生成都有本地 `ai_run_id`；远程执行时还有 `remote_run_id`。
3. 追溯证据：analysis、brief、blueprint、script 至少能追溯到章节、chunk 或 source trace。
4. 失败证据：AI 失败、schema 错误、远程超时、长篇部分失败都不会污染数据库。
5. UI 证据：用户从项目详情页能一路完成源稿导入、策略选择、蓝图生成、试播生成和进入工作台，且主流程不出现“方案草稿”。
