## 1. 文档目的

本文档用于明确画布模块的页面布局、节点体系、交互规则、鼠标事件、状态反馈和验收标准。

画布的核心产品形态是：**镜头编排 + 生成验证 + 资产沉淀**。

本次升级的业务心智是：先让画布成为可靠的创作闭环，再逐步增强智能能力。用户应能把素材放进画布，基于素材生成新结果，查看和选择历史版本，把满意结果保存到资产库，并从资产回到来源画布继续创作。

本文档写完后，应直接支撑以下工作：

- 产品确认画布模块到底怎么用
- 设计输出页面和交互稿
- 前端按页面区域和交互细节开发
- 后端明确哪些动作只是前端交互，哪些需要真实生成能力
- 测试按节点、菜单、鼠标事件和状态反馈验收

## 2. 模块定位

画布模块不绑定短剧项目或分集，不替代短剧制作流程；画布默认以”镜头主线 + 素材参考 + 生成结果”的结构服务短剧创作，同时保留独立、自由、可复用的创作空间属性。

画布模块解决的问题不是”自动生产一部短剧”，而是：

- 用户需要一个以镜头为主线组织内容的创作空间
- 用户需要把角色、场景、图片、视频、音频放到同一个画面中编排
- 用户需要先理清镜头关系，再决定是否继续生成
- 用户需要把画布里形成的新结果沉淀到资产；其中真实资产闭环归入 `0.23.0`

画布的核心使用路径是：

1. 用户描述创意、导入剧本或上传素材
2. 系统帮用户生成可编辑的镜头草稿节点
3. 用户验证和调整镜头（修改描述、关联角色/场景、调整景别运镜）
4. 触发生成验证结果（画面、视频、配音）
5. 满意的结果沉淀到资产库

当前版本画布模块不承担以下职责：

- 不承担短剧项目管理
- 不承担短剧流程跳转
- 不绑定短剧分集，不成为 episode 子资源
- 不承担全局任务中心职责
- 不承担资产库统一管理职责
- 不承担审片工作台职责

未来可支持但不属于当前版本：

- 从短剧某一集发送镜头到画布探索
- 画布关联短剧项目的可选来源标识

### 2.1 版本口径

本文档按两层口径验收：

- `0.21.x / 0.22.x 基线`：画布列表、画布编辑器、节点体系、对话栏开关、资产引用、基础运行反馈和占位入口。
- `0.23.0 补齐项`：画布上传真实流程、保存选中结果到资产、节点生成历史可见可选、画布生成结果真实写入资产库、资产库可搜索/预览/下载画布产物、资产来源可回到对应画布。
- `升级项`：在不改变画布独立模块定位的前提下，增强对话驱动、镜头局部生成、多素材快速生成和资产语义调用能力；升级项按后续版本逐步落地，工程规格见本文 `18. 研发需求规格`。

凡涉及“真实沉淀资产”“已落资产库”“上传真实可用”“保存选中结果到资产真实可用”“生成历史可见可选”的条目，默认属于 `0.23.0` 验收范围，除非条目中明确写为当前基线。

### 2.2 升级原则

本次升级参考 OiiOii 动画创作工作台中的高价值体验，但只吸收适合小窗画布定位的部分。

升级原则如下：

- 保留画布作为独立自由编排空间，不重构为短剧主工作台
- 画布默认以镜头主线组织内容，当画布内有镜头节点时，界面自动呈现制作型体验
- 保留节点、连线、资产引用和自动保存等现有结构
- 先补齐上传、生成历史、资产保存和来源追溯，再增强”对话推动创作”和”右键快速生成”
- 增强镜头、角色、场景和素材之间的创作语义，而不是只做通用文件管理
- 产品文案面向制作人员，用”镜头”而非”分镜”；技术字段保留 storyboard

本次升级重点借鉴以下方向：

- 对话栏是画布的主控面，用户通过自然语言驱动画布上的一切操作——创建节点、修改内容、编排关系、触发生成、沉淀资产
- AI 代理拥有完整画布上下文，通过 Skill 执行层操作画布
- 镜头不只是一张普通卡片，还应支持局部修改、单镜头生成、批量生成和历史选择；其中生成历史选择优先进入 `0.23.0`
- 角色、场景等资产需要具备”连到镜头 / 作为参考”的创作语义
- 多个图片、视频、镜头被选中后，应支持快速生成新素材或镜头
- 画布中的生成结果应能进入资产库，后续再被其他画布或创作链路调用

当前版本画布模块只有一个主页面：

| 页面 | 页面目标 | 进入方式 | 页面结果 |
|------|----------|----------|----------|

## 4. 页面布局

### 4.1 总体布局

画布编辑页采用”顶部栏 + 中央画布 + 左右悬浮面板 + 左侧工具栏”的布局。

页面从上到下、从左到右的固定结构如下：

1. 顶部栏
2. 中央无限画布区
3. 左侧浮动工具栏
4. 左侧对话栏（可展开/收起）
5. 右侧检视面板
6. 右键菜单与弹层

### 4.2 顶部栏布局

顶部栏固定在页面顶部，高度为单行工具栏。

顶部栏从左到右包含以下区域：

- 返回按钮
- 画布标题
- 保存状态
- 画布进度（当画布内存在镜头节点时显示）
- 对话栏开关
- 批量生成按钮
- 运行状态或取消动作
- 合成导出按钮

顶部栏交互要求：

- 点击返回按钮，返回画布列表页
- 点击画布标题，进入标题重命名状态
- 标题输入框按 `Enter` 提交，按 `Esc` 取消，失焦提交
- 保存状态需要展示 `准备中 / 编辑中 / 保存中 / 已保存 / 保存失败`
- 画布进度展示格式：`镜头 N · 图片 X/N · 视频 Y/N · 配音 Z/N · 通过 W/N`
- 画布进度在不存在镜头节点时不显示
- 对话栏开关用于展开或收起左侧对话栏
- 非运行中显示 `批量生成` 和 `合成导出` 按钮
- 运行中显示进度和取消动作

### 4.3 中央画布区布局

中央画布区是页面主操作区，承载节点、连线、缩放、拖拽、选择等交互。

画布区要求如下：

- 支持无限平移的点阵背景
- 支持缩放
- 支持节点自由摆放
- 支持节点之间连线
- 支持空白区域双击快速创建节点
- 支持空白区域右键菜单

### 4.4 左侧工具栏布局

左侧工具栏垂直悬浮在画布左侧中部，分为上下两块：制作步骤区和快捷工具区。

制作步骤区（上方）：

- 创意：导入剧本、描述创意生成镜头
- 素材：上传素材、引用资产
- 镜头：添加镜头、调整镜头内容
- 生成：单镜头生成、批量生成
- 沉淀：保存选中结果到资产

快捷工具区（下方）：

- 添加镜头
- 上传素材
- 引用资产
- 自动布局（提供布局选项：镜头主线布局 / 紧凑布局 / 自由整理）
- 撤销
- 重做

每个按钮要求：

- 鼠标悬停显示 tooltip
- 点击后直接执行动作或打开对应弹层
- 不可用时显示禁用态

### 4.5 左侧对话栏布局

左侧对话栏是一个可展开/收起的悬浮面板，默认展开。

对话栏结构如下：

- 头部：创作助手标题、收起按钮
- 中部：消息流
- 底部：输入框、发送按钮、输入提示

对话栏交互要求：

- 收起后以悬浮按钮形式保留入口
- 展开后宽度固定
- 输入框 `Enter` 发送，`Shift + Enter` 换行
- 发送后消息进入消息流
- 运行中需要显示处理中提示

### 4.6 右侧检视面板布局

右侧检视面板悬浮在页面右侧。

右侧检视面板结构如下：

- `镜头` Tab：选中节点时显示镜头详情编辑器；未选中时显示画布级进度
- `生成` Tab：当前节点可执行的生成动作
- `历史` Tab：当前节点的结果版本选择
- `进度` Tab：画布整体制作进度

镜头 Tab 要求：

- 未选中节点时，展示画布级进度（镜头数、已出图、已出视频、已配音、已通过）
- 选中镜头节点后，展示镜头完整编辑器（标题、描述、台词、角色、场景、景别、运镜、时长、状态）
- 选中非镜头节点后，展示该节点属性编辑器
- 节点进入业务动作模式时，展示动作标题和目标节点上下文

生成 Tab 要求：

- 选中镜头节点时，展示可执行生成动作（生成画面、生成视频、生成配音、重新生成）
- 选中图片节点时，展示可执行生成动作（生成画面、作为参考生成、生成视频）
- 未选中时，展示空状态提示

历史 Tab 要求：

- 展示当前节点的结果版本列表
- 每条结果展示缩略图、生成时间、模型或动作来源
- 支持选择某条结果作为当前结果
- 支持下载历史结果
- `0.23.0` 起支持保存历史结果到资产

进度 Tab 要求：

- 展示画布整体制作进度
- 展示镜头总数和各状态数量（已出图、已出视频、已配音、已通过、需返工）
- 展示失败任务数量
- 仅承担进度查看，不直接承担节点编辑

## 5. 工作区说明

画布编辑页只有一种工作区，不存在模式切换。用户可以在同一工作区内自由使用所有能力。

### 5.1 交互架构：对话为主控面，画布为共享状态

画布的交互架构是 **Skill 驱动 AI 代理模型**：

- **对话栏是主控面**。用户通过自然语言驱动画布上的一切操作——创建节点、修改内容、编排关系、触发生成、沉淀资产。
- **画布图是共享状态**。对话和手动编辑操作同一个画布图，任何一方的修改都实时反映到另一方。
- **Skill 是执行层**。AI 解析用户意图后调用 Skill 执行，Skill 的结果落回画布图和对话流。
- **手动编辑是直接操作**。用户可以直接拖拽节点、连线、右键、编辑属性，无需经过对话。手动操作和对话操作等价，共享同一个画布状态和历史栈。

```
用户自然语言 ──→ AI 代理 ──→ Skill 执行 ──→ 画布图变更
     ↑                                            │
     └────────────── 结果反馈 ←──────────── 对话流 ←┘

用户手动操作 ──→ 画布图变更 ──→ 自动保存
```

### 5.2 对话栏

对话栏是一个可展开/收起的悬浮面板，默认展开。

对话栏展开时：

- 显示在画布左侧
- 对话栏拥有完整画布上下文：当前所有节点、连线、选中状态、最近操作
- 用户通过对话可执行任何画布操作：创建/修改/删除节点、建立/删除连线、触发生成、保存资产
- 对话中引用画布节点时，目标节点在画布上高亮
- 仍然允许手动编辑节点和连线，手动操作不影响对话上下文连续性

对话栏收起时：

- 以悬浮按钮形式保留入口
- 画布主操作区变宽

对话能力的交付节奏：

- `0.23.0`：对话开放 3 个 Skill（`create_nodes / update_node / add_to_context`），形成"描述创意 → 生成草稿 → 调整内容"最小闭环。其余操作用户仍通过手动完成，AI 应回退为"请手动操作"提示。
- `0.24.0`：补齐 `delete_nodes / create_edge`，对话可删除节点和建立连线。
- `0.25.0`：补齐 `generate / delete_edge / save_to_assets`，对话可触发生成、删除连线、保存资产，对话可操作画布一切。
- 后续增强：对话上下文跨会话保持、对话回溯和撤销、对话引导式创作流程。

对话交互规则：

- 对话产生的每一步结果都必须落到可见节点或可见状态中，不只停留在消息流里
- 对话生成的节点和手动创建的节点在画布上没有视觉区别
- 对话触发的生成和右键触发的生成写入同一个 `results` 数组
- 对话修改节点后，右侧镜头控制台实时同步
- 对话操作失败时不产生脏节点，节点保持原状

### 5.3 画布 Skill 清单

画布的 AI 代理通过以下 8 个 Skill 操作画布。按版本节奏逐步开放。

| Skill | 作用 | 等价手动操作 | 版本 |
|-------|------|-------------|------|
| `canvas.create_nodes` | 创建一个或多个节点 | 左侧工具栏添加节点、双击空白创建 | `0.23.0` |
| `canvas.update_node` | 修改节点字段 | 右侧镜头控制台编辑 | `0.23.0` |
| `canvas.add_to_context` | 把节点/资产加入对话上下文 | 无等价手动操作，对话专属 | `0.23.0` |
| `canvas.delete_nodes` | 删除一个或多个节点 | 键盘 Delete、右键删除 | `0.24.0` |
| `canvas.create_edge` | 建立节点间连线 | 端口拖拽连线 | `0.24.0` |
| `canvas.delete_edge` | 删除连线 | 点击连线后删除 | `0.25.0` |
| `canvas.generate` | 触发生成（图片/视频/音频） | 右键快速生成、执行节点运行 | `0.25.0` |
| `canvas.save_to_assets` | 保存结果到资产库 | 右键保存选中结果到资产 | `0.25.0` |

Skill 规则：

- 每个 Skill 的输入输出有明确的 JSON Schema，AI 代理按 Schema 调用
- Skill 执行结果必须回写到画布图和对话流
- Skill 按破坏性分两级确认：
  - **直接执行**：`create_nodes / add_to_context`——操作可逆或无副作用
  - **需确认**：`update_node / delete_nodes / create_edge / delete_edge / generate / save_to_assets`——操作修改现有数据或不可逆
- `canvas.generate` 内部复用 `BusinessActionService`，与右键快捷生成走同一条数据路径
- 未开放的 Skill 在对话中不可调用，AI 应回退为"请手动操作"提示

#### 5.3.1 `0.23.0` 对话最小闭环

`0.23.0` 只开放 3 个 Skill，形成"描述创意 → 生成草稿 → 调整内容"的最小闭环：

1. 用户描述创意 → AI 调用 `canvas.create_nodes` → 生成 3-5 个 storyboard 节点
2. 用户说"把第三个镜头改成雨夜近景" → AI 调用 `canvas.update_node` → 目标节点更新
3. 用户说"看一下这个角色" → AI 调用 `canvas.add_to_context` → 角色信息进入对话上下文

其他操作（删除、连线、生成、保存资产）用户仍通过手动操作完成。

#### 5.3.2 `0.24.0` 对话编排闭环

补齐节点编排和结构操作：

- `canvas.delete_nodes`：对话删除节点
- `canvas.create_edge`：对话建立连线（含角色/场景连到镜头）

形成"对话调整画布结构"闭环。

#### 5.3.3 `0.25.0` 对话全操作闭环

补齐生成、删除连线、保存资产：

- `canvas.generate`：对话触发生成
- `canvas.delete_edge`：对话删除连线
- `canvas.save_to_assets`：对话保存资产

至此对话可操作画布一切。

### 5.4 进度面板

进度面板显示在右侧检视面板的”进度”Tab 中。

进度面板要求：

- 展示画布整体制作进度
- 展示镜头总数和各状态数量
- 展示失败任务数量
- 仅承担进度查看，不直接承担节点编辑

### 5.5 首选创作引导

画布的核心产品形态是：**镜头编排 + 生成验证 + 资产沉淀**。

用户进入空画布时，首选引导路径是：

1. 描述创意、导入剧本或上传素材
2. AI 生成可编辑的镜头草稿节点
3. 用户通过对话或手动调整镜头
4. 触发生成验证结果
5. 满意的结果沉淀到资产库

用户也可以跳过对话引导，直接手动添加节点和连线，两种方式不互斥。

### 5.6 对话栏收起/展开规则

- 收起/展开只改变界面呈现，不修改节点和连线数据
- 展开后画布内容必须完整保留
- 收起后画布主操作区自动延展

### 5.7 画布布局原则

画布默认以镜头主线组织内容，当画布内有镜头节点时，界面自动呈现制作型体验。

默认布局结构：

```text
角色 / 场景 / 参考素材
        ↓
镜头 01 → 镜头 02 → 镜头 03 → ...
   ↓        ↓        ↓
图片 / 视频 / 音频结果
```

布局规则：

- 镜头节点默认按镜头编号从左到右顺序排列，形成镜头主线
- 角色/场景节点默认排列在镜头主线上方，通过端口连线关联到具体镜头
- 图片/视频/音频执行结果节点默认排列在镜头主线下方
- 用户仍可自由移动节点，默认布局不锁定
- 自动布局提供三种模式：`镜头主线布局`（默认）、`紧凑布局`、`自由整理`

镜头节点状态展示：

每个镜头卡片直接展示以下信息：

- 镜头编号
- 画面缩略图
- 镜头描述
- 关联角色
- 关联场景
- 时长
- 状态：`待生成 / 生成中 / 待审 / 已通过 / 需返工`
- 当前结果版本号

## 6. 节点体系

### 6.1 节点分层

当前版本节点分为两类：

- 内容节点
- 执行节点

内容节点用于承载创作对象和结果。
执行节点用于承载生成动作和流水线处理动作。

### 6.1.1 生成路径统一说明

画布的生成行为统一通过 `canvas.generate` Skill 执行，数据路径只有一条。用户有三种触发方式，最终都走同一条执行链路：

1. **连线到执行节点**：用户手动连线，触发执行节点运行。结果写入节点 `results`，DAG 中可见可追踪。
2. **右键快速生成**：用户右键选择生成动作，系统内部创建隐藏执行节点并触发运行。是方式 1 的快捷入口，不引入第二条数据路径。
3. **对话驱动生成**：用户在对话栏要求生成，AI 调用 `canvas.generate` Skill 触发运行。内部走 `BusinessActionService`，与方式 1/2 共享同一执行链路。

三种方式的生成结果统一写入节点 `results` 数组，统一进入生成历史。

### 6.2 内容节点清单

当前版本内容节点如下：

| 节点类型 | 来源 | 作用 | 页面表现 |
|------|------|------|------|
| 镜头节点 `storyboard` | 添加节点菜单 | 组织镜头、时长、画面描述、音频标记 | 大卡片，含图片区、镜头号、标题、描述、时长、状态 |
| 图片节点 `image` | 添加节点菜单、空白双击、引用图片资产 | 承载单张画面、图像中间结果 | 图片卡 |
| 角色节点 `character` | 引用角色资产、后续生成 | 承载角色形象与角色描述 | 圆形头像卡 |
| 场景节点 `scene` | 引用场景资产、后续生成 | 承载场景图和场景描述 | 16:9 场景卡 |
| 视频资产节点 `video-asset` | 引用视频资产 | 承载视频资产预览与播放 | 视频卡 |
| 音频资产节点 `audio` | 引用音频资产 | 承载音频资产预览与播放 | 音频卡 |

> 便签节点 `note` 不纳入当前版本。便签无生成能力、无端口、无资产语义，与画布"编排→生成→沉淀"主循环无关。后续版本视用户反馈决定是否引入。

### 6.3 执行节点清单

当前版本执行节点如下：

| 节点类型 | 作用 | 输入 | 输出 |
|------|------|------|------|
| 画面构想 `text-to-image` | 根据文字和参考图生成图片 | 文本、参考图 | 图片 |
| 图片转视频 `image-to-video` | 根据图片生成视频 | 图片 | 视频 |
| 文本转语音 `text-to-speech` | 根据文本和角色语音关系生成音频 | 文本、角色 | 音频 |
| 合成导出节点 `concat` | 汇总多个中间结果并导出 | 多路媒体输入 | 合成结果 |

> 合成节点吸收了原导出节点 `export` 的导出能力。合成节点的节点编辑区中包含"导出配置"区域，完成合成后可直接触发导出。不再单独设置导出节点，避免出现仅含"复制/删除"交互的无端口终端节点。

### 6.4 节点创建入口

当前版本节点创建有 5 种方式：

1. 左侧工具栏点击 `添加节点`
2. 空白画布右键，点击 `添加节点`
3. 空白画布双击，快速创建一个空图片节点
4. 左侧工具栏点击 `引用资产`，从资产弹层插入节点
5. 对话栏输入创意描述后，AI 调用 `canvas.create_nodes` Skill 生成镜头草稿节点（`0.23.0` 必做）

### 6.5 节点展示要求

所有节点必须遵守以下通用规则：

- 节点外层有统一卡片容器
- 节点可展示运行状态
- 节点支持选中态
- 节点支持端口显示
- 节点支持被拖拽
- 节点支持右键菜单

节点状态要求：

- `running` 显示顶部进度条
- `completed` 显示完成态
- `failed` 显示失败态
- `paused` 显示弱化态
- `selected` 显示高亮边框

镜头制作状态（仅镜头节点展示，与节点运行状态是两层独立维度）：

- `待生成`：镜头节点从未触发过生成，或所有历史结果已被删除
- `生成中`：镜头节点当前有运行中任务（对应运行状态 `running`）
- `待审`：镜头节点有至少一个生成结果，但用户尚未标记通过或需返工
- `已通过`：用户标记当前结果为通过
- `需返工`：用户标记当前结果为需返工

两层状态的关系：

- 镜头制作状态是业务状态，由生成结果和用户标记共同决定
- 节点运行状态是任务状态，反映当前是否有运行中的生成任务
- 一个镜头可以"需返工"且没有运行中任务
- 一个镜头可以"待审"且正在重新生成（`生成中`）

下表用于明确每一种节点在当前版本中允许什么展示和交互。

| 节点类型 | 默认创建方式 | 卡片展示重点 | 单击后 | 双击后 | 右键动作重点 | 可直接生成 |
|------|------|------|------|------|------|------|
| 镜头节点 `storyboard` | 添加节点 | 镜头号、标题、画面、描述、时长、景别、运镜、状态 | 选中并显示属性 | 打开完整编辑器 | 设镜头时长、生成画面、生成视频、标记通过/需返工、查看历史、复制、删除 | 是（快捷方式） |

## 7. 页面操作入口

### 7.1 左侧工具栏

#### 7.1.1 添加节点

- 点击后打开节点菜单
- 节点菜单分为 `内容节点` 和 `执行节点`
- 点击菜单项后，在当前可视区域中心插入节点
- 插入后节点进入选中态
- 插入后右侧镜头控制台切到该节点

#### 7.1.2 引用资产

- 点击后打开资产引用弹层
- 弹层包含 `角色 / 场景 / 图片 / 视频 / 音频` 五个分类
- 支持搜索
- 点击某个资产后，在当前可视区域中心插入对应节点
- 插入后自动关闭弹层
- 插入后节点进入选中态

#### 7.1.3 自动布局

- 点击后对当前节点进行自动布局
- 节点数量为 0 时按钮禁用
- 自动布局后保留节点内容，不改变节点业务数据

#### 7.1.4 撤销

- 点击后撤销上一步可回退操作
- 无可撤销内容时按钮禁用

#### 7.1.5 重做

- 点击后重做上一步撤销内容
- 无可重做内容时按钮禁用

### 7.2 空白画布右键菜单

空白画布右键菜单包含以下项：

- 上传
- 保存选中结果到资产
- 添加节点
- 撤销
- 重做
- 粘贴
- 快速生成（升级项）
- 多选（升级项）
- 描述创意，生成镜头草稿（升级项）

当前版本要求：

- `上传` 先保留为占位入口
- `保存选中结果到资产` 先保留为占位入口；无选中结果时禁用
- `添加节点` 打开二级节点菜单
- `撤销 / 重做 / 粘贴` 需要真实可用

`0.23.0` 要求：

- `上传` 接入真实上传或明确可用的资产导入流程
- `保存选中结果到资产` 接入真实资产入库流程
- 完成后可在资产模块搜索、预览、下载，并可从资产来源回到当前画布
- `快速生成` 至少支持空白提示词或单节点生成，并把结果插入为可见节点

升级项要求：

- `多选` 优先支持键盘辅助点选，用于选择多个图片、视频、镜头或音频节点；框选作为后续增强，不进入 `0.23.0` 门禁
- `快速生成` 根据当前选中内容生成新图片、视频或镜头结果
- 没有选中内容时，`快速生成` 应进入提示词输入态
- 有选中内容时，`快速生成` 应自动把选中素材作为参考输入
- 快速生成结果默认插入当前可视区域，并与参考节点建立关系

### 7.3 节点右键菜单

节点右键菜单按节点类型展示不同动作。

#### 通用动作

所有可右键节点至少支持：

- 复制
- 删除
- 取消

#### 镜头节点专属动作

- 设镜头时长
- 生成画面（快捷方式：内部创建 text-to-image 隐藏节点）
- 生成视频（快捷方式：内部创建 image-to-video 隐藏节点）
- 标记通过 / 需返工
- 查看生成历史
- 选择历史结果

> 镜头节点的生成动作标注为"快捷方式"。正式路径是通过连线将执行节点（画面构想、图片转视频等）连接到镜头节点。快捷方式在镜头控制台和右键菜单均可触发，便于快速验证；正式路径在 DAG 中可见、可追踪。

#### 角色节点专属动作

- 连到镜头（拖拽端口连线或右键选择后点选目标镜头）
- 生成形象（快捷方式）
- 添加到对话

> 角色的"出演"语义通过角色端口连线到镜头节点实现（见 §11 连线规则），不再作为独立的右键动作。"换装""换表情"归入生成形象的参数选项，不作为独立右键动作。

#### 场景节点专属动作

- 连到镜头（拖拽端口连线或右键选择后点选目标镜头）
- 生成场景（快捷方式）
- 添加到对话

> 场景的"设为背景"语义通过场景端口连线到镜头节点实现（见 §11 连线规则），不再作为独立的右键动作。"换时段""换天气"归入生成场景的参数选项，不作为独立右键动作。

#### 画面相关动作

镜头节点或图片节点可触发：

- 生成画面（快捷方式：内部创建 text-to-image 隐藏节点）
- 作为参考生成（连线到 text-to-image 执行节点）
- 生成视频（快捷方式：内部创建 image-to-video 隐藏节点）

#### 语音相关动作

文本转语音或角色语音相关节点可触发：

- 生成音频（通过连线到 text-to-speech 执行节点触发）
- 替换音色（修改 text-to-speech 节点的角色引用）
- 试听

#### 多节点动作（升级项）

当用户选中多个素材或镜头节点时，右键菜单可展示以下动作：

- 根据选中内容生成图片
- 根据选中内容生成视频
- 合成选中镜头
- 保存选中结果到资产（`0.23.0` 真实入库）
- 下载选中结果（存在可下载地址时）

多节点动作不改变当前版本“不做批量属性编辑”的边界，只用于明确的生成、合成、保存和下载动作。

## 8. 右侧镜头控制台与节点编辑区

### 8.1 打开方式

右侧镜头控制台或节点编辑区在以下场景打开：

- 双击节点
- 插入节点后自动显示
- 选中节点后点击右侧 `镜头` Tab
- 节点触发业务动作后自动进入动作编辑态

### 8.2 常规编辑态

常规编辑态需要支持以下字段：

- 资产名称或节点名称
- 分类
- 描述或 Prompt
- 图片预览
- 引用其他节点

常规编辑态底部操作要求：

- 左侧为 `完成`
- 右侧为 `生成` 按钮（仅可生成节点显示）
- 生成按钮标注为"快捷方式"，正式路径是连线到执行节点

### 8.3 业务动作编辑态

业务动作编辑态是从右键菜单进入的专门生成面板。

该状态下必须展示：

- 当前动作名称
- 目标节点名称
- 可填写的动作描述
- 可选风格标签
- 可选模型
- 可选画面比例
- 可选参考素材
- 取消按钮
- 生成按钮

业务动作编辑态升级要求：

- 从镜头、图片、角色、场景触发时，面板需要展示该节点的关键上下文
- 如果动作来自多选，面板需要展示已选素材数量和类型
- 用户可以在动作描述中继续用自然语言补充要求
- 生成成功后，新结果应回填到目标节点或作为新节点插入画布
- 生成失败后保留用户输入，允许重试

### 8.4 图片上传交互

属性编辑区图片区域需要支持：

- 点击上传
- 拖拽图片到区域内上传
- 上传中显示 loading
- 有图时显示预览
- 非业务动作态允许替换图片

### 8.5 生成历史选择（0.23.0）

图片、视频、镜头和执行节点需要支持结果历史入口。

历史入口要求：

- 展示该节点曾经生成过的结果
- 每条历史结果至少展示缩略图、生成时间、模型或动作来源
- 用户可选择某条历史结果作为当前结果
- 用户可下载历史结果
- `0.23.0` 起，用户可将历史结果保存到资产
- 历史选择只影响当前节点展示结果，不删除其他历史记录

## 9. 鼠标事件与交互规则

这一节是画布模块开发必须遵守的鼠标交互规格。

### 9.1 空白区域交互

#### 单击空白区域

- 清除当前选中节点
- 关闭节点右键菜单
- 如果当前处于连线引导态（如角色/场景"连到镜头"），不清除状态，保持继续选择目标镜头

#### 双击空白区域

- 在双击位置创建一个空图片节点
- 节点位置需要避让已有节点
- 新节点创建后自动选中
- 右侧镜头控制台切到该节点

#### 右击空白区域

- 打开画布右键菜单
- 菜单锚点以鼠标点击位置为准
- 不得打开节点右键菜单

### 9.2 节点交互

#### 单击节点

- 选中该节点
- 高亮节点边框
- 右侧镜头控制台切换到该节点

#### 双击节点

- 选中该节点
- 直接打开完整属性编辑器

#### 右击节点

- 打开节点右键菜单
- 菜单位置跟随鼠标点击位置
- 阻止浏览器原生右键菜单

#### 拖拽节点

- 鼠标按下节点后可拖拽移动
- 拖拽过程中实时更新视觉位置
- 拖拽结束后写入历史栈
- 拖拽结束后触发保存状态进入编辑中

#### 删除节点

- 可通过键盘 `Delete / Backspace`
- 可通过节点右键菜单删除
- 删除后需要提示 `已删除 X 个节点`
- 提示中必须提供 `撤销`

#### 复制节点

- 可通过节点右键菜单复制
- 可通过快捷键 `Ctrl/Cmd + D` 复制当前选中节点
- 复制后的新节点默认偏移一定距离，避免完全重叠

### 9.3 角色/场景连到镜头（`0.23.0` 结构优化项）

角色节点和场景节点通过端口连线直接连接到镜头节点，不再使用独立的”关联模式”。此交互为 `0.23.0` 新增，替换原”关联模式”交互。

#### 角色连到镜头

交互步骤如下：

1. 用户从角色节点的输出端口（`角色` 类型）开始拖拽
2. 拖到镜头节点的输入端口（`角色` 类型）后完成连线
3. 角色引用写入目标镜头的 `context.main_character_ref`
4. 连线创建后写入历史栈

#### 场景连到镜头

交互步骤如下：

1. 用户从场景节点的输出端口（`场景` 类型）开始拖拽
2. 拖到镜头节点的输入端口（`场景` 类型）后完成连线
3. 场景引用写入目标镜头的 `context.scene_background_ref`
4. 连线创建后写入历史栈

#### 备选交互：右键连到镜头

用户也可以通过右键菜单触发连线：

1. 用户右击角色/场景节点
2. 点击 `连到镜头`
3. 画布进入连线引导态，光标变为十字
4. 用户单击一个镜头节点
5. 在镜头的对应输入端口完成连线
6. 弹出成功提示并退出连线引导态

规则要求：

- 连线引导态中，点击的目标如果不是镜头节点，提示”请选择一个镜头节点”
- 连线成功后自动退出连线引导态
- 按 `Esc` 可取消连线引导态

#### 连线校验

- 角色端口只能连到镜头节点的 `角色` 输入端口
- 场景端口只能连到镜头节点的 `场景` 输入端口
- 一个镜头节点最多连接 1 个角色和 1 个场景；重复连线时替换旧引用

### 9.4 连线交互

#### 连线开始

- 鼠标按下节点端口后开始拖出连线
- 连线预览跟随鼠标移动

#### 连线结束

- 拖到合法目标端口后完成连线
- 完成后写入历史栈

#### 连线校验

- 非法端口组合不得创建连线
- 非法连接时只允许视觉拒绝，不得生成脏数据

#### 连线删除

- 删除边时写入历史栈
- 删除后不影响节点本身内容

### 9.5 多选规则

`0.21.x / 0.22.x 基线`：底层允许按 `Shift / Meta / Control` 进行多选键位接管，但产品规格上不把多选作为正式能力对外承诺。

基线要求如下：

- 文档验收不以多选为主能力
- 不设计多选后的批量编辑面板
- 不设计多选后的批量右键菜单
- 如果底层框架出现临时多选表现，不作为正式产品能力说明

升级项要求如下：

- `0.23.0` 最小多选只要求 `Shift / Meta / Control` 点选和已选节点动作，不要求框选
- 多选只用于快速生成、合成、保存、下载等明确动作
- 多选不进入批量属性编辑
- 多选后右键菜单只展示当前可执行的动作
- 多选素材生成新结果时，系统需要把选中节点记录为参考来源
- 生成结果应与选中节点建立关系，便于后续追溯

### 9.6 画布移动与缩放

#### 拖拽平移

- 鼠标拖动画布空白区域可平移视野
- 平移结束后记录 viewport

#### 滚轮缩放

- 鼠标滚轮控制缩放
- 缩放范围必须受最小值和最大值限制

#### 控件缩放

- 左下角缩放控件可放大、缩小、重置视野

### 9.7 悬停反馈

当前版本需要最少支持以下悬停反馈：

- 工具栏按钮悬停显示 tooltip
- 节点 hover 显示可点击感
- 可替换图片区域 hover 显示替换提示
- 禁用按钮 hover 保持禁用态，不触发动作

### 9.8 当前版本不做的鼠标交互

为了避免开发误解，当前版本明确不做以下内容：

- 不做批量移动后的批量属性编辑
- 不做节点拖入资产库的拖放交互
- 不做节点之间的框选成组
- 不做资产卡片拖拽进画布

说明：

- `0.21.x / 0.22.x 基线` 不承诺多节点框选
- 升级项可引入面向快速生成的多选，但不扩展为完整框选分组能力

## 10. 画布与资产交互

### 10.1 资产引用

画布当前只支持“点击资产后插入节点”，不支持拖拽资产到画布。

插入规则如下：

- 角色资产插入为角色节点
- 场景资产插入为场景节点
- 图片资产插入为图片节点
- 视频资产插入为视频资产节点
- 音频资产插入为音频资产节点

### 10.1.1 资产语义调用（升级项）

资产引用不只承担“插入节点”，还需要逐步支持创作语义。

角色资产语义：

- 连到镜头：将角色通过端口连线写入镜头的角色引用，用于生成时作为角色参考
- 添加到对话：把角色信息带入左侧对话上下文

场景资产语义：

- 连到镜头：将场景通过端口连线写入镜头的场景引用，用于生成时作为背景参考
- 作为场景参考：用于生成图片或视频时的环境参考
- 添加到对话：把场景描述带入左侧对话上下文

图片 / 视频 / 音频资产语义：

- 作为参考生成：把资产作为生成动作输入
- 加入镜头：把资产写入目标镜头的画面、视频或音频字段
- 添加到对话：把资产带入对话上下文，便于自然语言修改

### 10.2 结果沉淀

`0.21.x / 0.22.x 基线`：

- 画布允许生成图片、视频、音频等中间结果
- 生成结果可回填到画布节点或执行节点
- 资产引用弹层可把已有资产插入画布

`0.23.0` 要求：

- 生成后的图片、视频、音频结果可真实沉淀为资产
- 上传到画布的图片、视频、音频可按规则沉淀为资产
- 沉淀后在资产模块中可查看、搜索、预览、下载
- 资产来源可打开并回到对应画布
- 画布不承担资产统一管理

### 10.3 画布产物复用（升级项）

画布产物进入资产库后，需要支持再次回到画布使用。

复用要求：

- 资产库中的画布产物可再次插入任意画布
- 角色、场景资产保留可通过端口连线到镜头的语义
- 图片、视频、音频资产保留原始来源画布和节点信息
- 从资产库打开来源时，应回到对应画布；如能定位到节点，则优先定位到来源节点

## 11. 连线与端口规则

### 11.1 端口规则

当前版本端口类型采用强类型约束，至少包含以下类型：

- `text`
- `image`
- `video`
- `audio`
- `character`
- `scene`
- `storyboard`

规则要求：

- 同一节点不能连接到自己
- 两端都有端口类型时，必须按类型兼容规则校验
- 两端都没有端口类型时，允许作为普通关系线存在
- 一端有类型、一端无类型时，禁止连接

### 11.2 主要节点端口表

| 节点类型 | 输入端口 | 输出端口 |
|------|------|------|
| 镜头节点 `storyboard` | 图片、音频、视频、角色、场景 | 视频 |
| 图片节点 `image` | 图片 | 图片 |
| 角色节点 `character` | 无 | 角色 |
| 场景节点 `scene` | 无 | 场景 |
| 视频资产节点 `video-asset` | 无 | 视频 |
| 音频资产节点 `audio` | 无 | 音频 |
| 画面构想 `text-to-image` | 文本、图片参考 | 图片 |
| 图片转视频 `image-to-video` | 图片、动态描述文本 | 视频 |
| 文本转语音 `text-to-speech` | 台词文本、角色 | 音频 |
| 合成导出节点 `concat` | 多路媒体结果 | 合成结果 |

> 镜头节点新增 `角色` 和 `场景` 输入端口（`0.23.0` 结构优化项）。角色节点和场景节点可直接通过端口连线到镜头，不再需要独立的"关联模式"。

### 11.3 连线规则表

下表是当前版本必须重点支持的连接关系。

| 起点节点 | 终点节点 | 是否允许 | 说明 |
|------|------|------|------|
| 图片节点 | 图片转视频 | 允许 | 静态图生成镜头视频 |
| 图片节点 | 画面构想 | 允许 | 作为参考图继续生图 |
| 角色节点 | 文本转语音 | 允许 | 指定谁来配音 |
| 角色节点 | 镜头节点 | 允许 | 角色连线写入镜头角色引用（`0.23.0` 结构优化项） |
| 场景节点 | 镜头节点 | 允许 | 场景连线写入镜头场景引用（`0.23.0` 结构优化项） |
| 音频节点 | 镜头节点 | 允许 | 作为镜头配音输入 |
| 视频节点 | 镜头节点 | 允许 | 作为镜头视频输入 |
| 图片节点 | 镜头节点 | 允许 | 作为镜头画面输入 |
| 画面构想 | 图片节点 | 允许 | 生成结果回填图片节点 |
| 图片转视频 | 镜头节点 | 允许 | 视频结果回填镜头 |
| 文本转语音 | 镜头节点 | 允许 | 音频结果回填镜头 |
| 镜头节点 | 合成导出节点 | 允许 | 镜头输出进入合成 |
| 视频节点 | 角色节点 | 不允许 | 端口类型不兼容 |
| 音频节点 | 场景节点 | 不允许 | 端口类型不兼容 |

升级项补充规则：

| 起点节点 | 终点节点 | 是否允许 | 说明 |
|------|------|------|------|
| 多个图片节点 | 图片转视频 | 允许 | 多图参考生成视频 |
| 多个图片节点 | 镜头节点 | 允许 | 多图参考补充镜头画面 |
| 镜头节点集合 | 合成导出节点 | 允许 | 按顺序合成片段 |
| 任意素材节点 | 对话上下文 | 允许 | 添加到对话后作为自然语言生成上下文 |

### 11.4 连线反馈要求

- 鼠标拖拽到合法端口时，端口应表现为可连接状态
- 鼠标拖拽到非法端口时，不允许落线
- 非法连接不得写入边数据
- 删除连线后，节点本身保持不变

### 12.2 空状态线框

空画布时，中间需要出现一张引导卡，引导用户走核心路径。

```text
                +--------------------------------------------+
                |                                            |
                |         这个画布还没有镜头                 |
                |                                            |
                |   导入剧本、上传素材，或描述一个创意       |
                |   我会帮你生成可编辑的镜头草稿             |
                |                                            |
                |   +--------------------------------------+ |
                |   | 输入创意描述...                       | |
                |   +--------------------------------------+ |
                |                              [ 生成镜头 ] |
                |                                            |
                |   ────── 或从素材开始 ──────               |
                |                                            |
                |   [ 导入剧本生成镜头 ]                     |
                |   [ 上传图片/视频 ]   [ 引用资产 ]         |
                |                                            |
                |   双击画布任意位置可快速创建图片节点       |
                +--------------------------------------------+
```

空状态引导原则：

- 首选动作是"描述创意，生成镜头草稿"，引导用户走画布核心路径
- 新增"导入剧本生成镜头"入口，适合已有剧本的用户（`0.23.0` 等价于在对话栏粘贴剧本文本描述创意，不额外做文件解析入口）
- 备选动作是"上传素材"或"引用资产"，适合已有素材的用户
- 底部保留"双击快速创建"提示，满足高级用户需求
- 第一个节点创建后引导卡自动消失

### 12.3 右侧镜头控制台线框

右侧镜头控制台的常规结构如下：

```text
+----------------------------------+
| 镜头 / 生成 / 历史 / 进度    收起 |
+----------------------------------+
| 图片预览 / 音频预览 / 视频预览     |
|----------------------------------|
| 资产名称 / 节点名称输入框          |
| 分类按钮组                        |
| Prompt / 描述输入区               |
| 引用节点区                        |
|----------------------------------|
| 完成                    生成按钮  |
+----------------------------------+
```

## 13. 保存与反馈

### 13.1 自动保存

- 图谱编辑内容采用自动保存
- 自动保存需有防抖
- 节点、边、viewport 变化后进入待保存状态

### 13.2 手动保存

- 支持 `Ctrl/Cmd + S` 手动保存
- 手动保存成功后更新保存状态
- 手动保存失败需明确报错

### 13.3 保存冲突策略

自动保存和手动保存可能并发触发，需要遵守以下策略：

- 自动保存只保存已完成编辑的字段（输入框 blur 后），不保存当前正在 focus 的输入框内容
- 手动保存优先级高于自动保存；手动保存触发时，取消待执行的自动保存
- 保存失败重试 3 次后提示用户"保存失败，请检查网络后重试"
- 保存中的状态不可触发新的保存请求，避免并发写入

### 13.4 运行反馈

- 节点运行中显示运行状态
- 节点失败时显示失败状态
- 成片运行中顶部显示进度
- `0.21.x / 0.22.x 基线`：成片完成提示“生成完成”
- `0.23.0`：真实写入资产后才提示“已落资产库”

升级项要求：

- 单节点生成中，节点自身展示进度
- 多选快速生成中，画布顶部展示整体进度，相关节点展示参与状态
- 生成完成后，目标节点或新节点高亮展示
- 如果生成结果进入历史记录，应提示“已加入历史”
- 如果生成失败，应保留输入和参考来源，允许用户重试

### 13.5 空状态

当画布没有任何节点时，必须展示空状态引导卡。

空状态要求：

- 首选引导用户"描述创意，生成镜头草稿"
- 备选提供"上传素材"和"引用资产"入口
- 底部保留"双击空白处快速创建"提示
- 第一个节点创建后引导卡自动消失

## 14. 页面流转

### 14.1 进入页面

- 从首页进入画布
- 从侧边入口进入画布
- 从画布列表页进入画布

### 14.2 页面内流转

- 添加节点后停留在当前页继续编辑
- 引用资产后停留在当前页继续编辑

- `0.23.0` 真实沉淀到资产后，用户可继续留在画布或再去资产查看

### 14.3 离开页面

- 点击返回进入画布列表

## 16. 验收清单

### 16.1 布局验收

- 页面是否按顶部栏、画布区、左右悬浮区组织
- 左右面板是否不会破坏画布主工作区
- 对话栏展开/收起后布局是否正确变化

### 16.2 节点验收

- 内容节点和执行节点是否能按清单创建（6 种内容 + 4 种执行 = 10 种）
- 节点是否展示正确字段
- 节点是否支持选中、拖拽、删除、复制、右键
- 镜头节点是否支持历史结果选择
- 图片、视频、执行节点是否有生成历史入口
- 合成导出节点是否包含导出配置和导出触发

### 16.3 鼠标交互验收

- 单击空白是否取消选中
- 双击空白是否创建节点
- 单击节点是否选中
- 双击节点是否打开编辑
- 右击空白是否打开画布菜单
- 右击节点是否打开节点菜单
- 拖拽节点后是否正确落位
- 连线拖拽是否正确校验
- 角色端口是否能连到镜头节点
- 场景端口是否能连到镜头节点
- 右键"连到镜头"引导态是否能正确进入、取消、完成
- 多选后是否只出现明确可执行的快速生成、合成、保存、下载动作（升级项）

### 16.4 节点与连线规则验收

- 节点交互矩阵是否和实际行为一致
- 各节点字段是否按规格展示
- 端口表和连线规则表是否被正确实现
- 非法连接是否被阻止

### 16.5 资产交互验收

- 是否能从资产引用弹层插入角色、场景、图片、视频、音频节点
- `0.21.x / 0.22.x 基线`：是否能把已有资产引用进画布
- `0.23.0`：沉淀结果后是否能在资产模块查看、搜索、预览、下载，并打开来源回到画布
- 角色节点是否能通过端口连线到镜头节点（`0.23.0` 结构优化项）
- 场景节点是否能通过端口连线到镜头节点（`0.23.0` 结构优化项）
- 图片、视频、音频资产是否能作为参考输入参与快速生成（升级项）

### 16.6 状态验收

- 空状态是否正确显示"描述创意"引导和备选入口
- 第一个节点创建后空状态是否消失
- 保存状态是否正确变化
- 自动保存是否不保存正在编辑的输入框内容
- 手动保存是否优先于自动保存
- 生成中、成功、失败是否有反馈
- 删除节点后是否可撤销
- 生成历史是否可见、可选、可下载
- 对话驱动落节点失败时是否不产生脏节点（升级项）

### 16.7 对话驱动验收（升级项）

- 输入故事或大纲后，是否能生成可编辑的镜头草稿节点
- 在对话中修改指定镜头后，目标节点是否更新
- 在对话中要求增减镜头后，画布节点数量和顺序是否正确变化
- 把角色或场景添加到对话后，生成结果是否使用该上下文
- 对话生成结果是否能继续通过右侧镜头控制台编辑

## 17. 当前版本边界

`0.21.x / 0.22.x 基线` 画布模块只做以下闭环：

- 进入画布
- 添加节点（6 种内容 + 4 种执行）
- 引用资产
- 拖拽连线
- 编辑节点
- 触发生成（连线到执行节点为正式路径，右键快捷方式为便捷入口）
- 生成结果回填节点

`0.23.0` 补齐以下闭环：

- 画布上传真实流程
- 保存选中结果到资产真实流程
- 节点生成历史可见、可选择、可下载
- 画布生成结果真实沉淀资产
- 资产库查看、搜索、预览、下载画布产物
- 资产来源回到对应画布
- 角色/场景节点可通过端口连线到镜头节点（`0.23.0` 结构优化项，替换原”关联模式”）
- 合成导出节点（原合成+导出合并）
- **Skill 驱动 AI 对话代理**：对话栏拥有完整画布上下文，`0.23.0` 开放 3 个 Skill（create_nodes / update_node / add_to_context），形成"描述创意 → 生成草稿 → 调整内容"最小闭环

`0.24.0` 补齐以下体验：

- 对话删除节点（`canvas.delete_nodes`）
- 对话建立连线（`canvas.create_edge`，含角色/场景连到镜头）

`0.25.0` 补齐以下体验：

- 对话触发生成（`canvas.generate`）
- 对话删除连线（`canvas.delete_edge`）
- 对话保存资产（`canvas.save_to_assets`）
- 镜头批量生成和历史选择
- 多素材选择后的快速生成
- 图片、视频、音频资产作为参考输入

后续增强：

- 对话上下文跨会话保持
- 对话回溯和撤销
- 对话引导式创作流程

当前版本不扩展以下内容：

- 与短剧模块打通流转
- 画布承担项目管理
- 资产拖拽进画布
- 框选分组
- 批量编辑
- 便签节点
- 独立导出节点（已合并到合成节点）

升级后仍然不做以下内容：

- 不把画布改造成短剧项目管理页
- 不要求画布直接覆盖短剧源数据
- 不做多人实时协作
- 不做复杂版本分支合并
- 不做完整时间线剪辑工具
- 不做模式切换（画布只有一种工作区）

## 18. 研发需求规格

本节是画布升级的工程级需求规格，用于后端、前端、测试和任务拆分。若与前文业务描述存在粒度差异，以本节作为研发落地依据。

### 18.1 研发目标

在不重构现有画布、不替代短剧工作台的前提下，`0.23.0` 优先补齐两项工程能力：

**一、可信闭环**

1. 画布产物真实入资产库，并可从资产回到来源画布。
2. 画布上传入口真实可用，上传结果可生成节点并可入资产。
3. `保存选中结果到资产` 入口真实可用，支持节点结果和历史结果入库。
4. 节点生成结果支持历史记录、选择历史、下载和入库。
5. 最小快速生成支持空白提示词或单节点输入，并把生成结果插入为可见节点。

**二、Skill 驱动 AI 对话代理**

6. 对话栏拥有完整画布上下文（节点图、选中状态、最近操作）。
7. AI 代理解析用户自然语言意图，调用画布 Skill 执行操作。
8. `0.23.0` 开放 3 个 Skill：`canvas.create_nodes / update_node / add_to_context`，形成"描述创意 → 生成草稿 → 调整内容"最小闭环。
9. 需确认的 Skill（`update_node`）展示操作计划，用户确认后执行；直接执行的 Skill（`create_nodes / add_to_context`）即时生效。
10. Skill 执行结果回写到画布图和对话流，保持画布和对话双向同步。
11. 未开放 Skill 在对话中不可调用，AI 应回退为"请手动操作"提示。

`0.24.0` 补齐 Skill：

- `canvas.delete_nodes / create_edge`：对话删除节点和建立连线。

`0.25.0` 补齐 Skill：

- `canvas.generate / delete_edge / save_to_assets`：对话触发生成、删除连线、保存资产。对话可操作画布一切。

后续增强能力：

- 对话上下文跨会话保持。
- 对话回溯和撤销。
- 对话引导式创作流程（AI 主动推进下一步）。
- 业务动作支持多节点和资产语义输入。

非目标：

- 不做多人实时协作。
- 不做复杂版本分支合并。
- 不做完整时间线剪辑工具。
- 不做画布直接覆盖短剧源数据。
- 不做画布全量替代短剧工作台。
- 不把画布任务硬塞进传统 `tasks` 表；画布运行继续使用 `canvas_runs / canvas_tasks`。

### 18.2 现有技术基线

后端已有对象：

- `canvases`：画布主表。

- `canvas_edges`：当前工作态连线。
- `canvas_versions`：运行或快照版本。
- `canvas_runs`：一次画布运行。
- `canvas_tasks`：画布运行中的节点级任务。
- `assets`：通用媒体资产表，当前主要承载 image/video/audio。

已有接口：

- `GET /api/v1/canvases`
- `POST /api/v1/canvases`
- `GET /api/v1/canvases/:id`
- `PATCH /api/v1/canvases/:id`
- `POST /api/v1/canvases/:id/save`
- `POST /api/v1/canvases/:id/run`
- `GET /api/v1/canvases/:id/run-status`
- `POST /api/v1/canvases/:id/business-action`
- `GET /api/v1/assets`
- `POST /api/v1/assets/from-task`

前端已有基线：

- `usePipelineOrchestrator` 已具备对话落节点能力，但主要是前端本地编排。
- `BusinessActionService` 已支持部分单节点业务动作，并通过隐藏执行节点触发运行。

### 18.3 数据模型增量

第一阶段优先不新增表，所有新增字段写入：

- `canvas_nodes.data_json`
- `canvas_tasks.result_json`
- `assets.metadata_json`

不新增表的原因：

- 降低迁移成本。
- 避免重构当前画布存储模型。
- 便于快速验证资产闭环和生成历史。

#### 18.3.1 节点 `data_json` 规范

所有节点允许保存以下通用字段：

```ts
type CanvasNodeDataBase = {
  label?: string
  prompt?: string
  description?: string
  asset_id?: number | string
  source_asset_id?: number | string
  source_asset_kind?: 'image' | 'video' | 'audio' | 'character' | 'scene'
  source_asset_title?: string
  source_canvas_id?: string
  source_node_id?: string
  source_run_id?: string
  source_task_id?: string
  current_result_id?: string
  results?: CanvasNodeResult[]
  references?: CanvasReference[]
  generation?: CanvasGenerationConfig
  context?: CanvasSemanticContext
}
```

#### 18.3.2 节点结果结构

```ts
type CanvasNodeResult = {
  id: string
  kind: 'image' | 'video' | 'audio' | 'text'
  url?: string
  thumbnail_url?: string
  mime_type?: string
  title?: string
  prompt?: string
  provider?: string
  model?: string
  action_label?: string
  run_id?: string
  task_id?: string
  created_at: string
  asset_id?: number
  is_current?: boolean
  metadata?: Record<string, unknown>
}
```

规则：

- 每个节点最多保留 20 条 `results`。
- 新结果插入 `results[0]`。
- 当前结果由 `current_result_id` 标记。
- 图片节点兼容旧字段 `images`。
- 视频节点兼容旧字段 `videoUrl`。
- 音频节点兼容旧字段 `audioUrl / url`。

并发写入保护：

- `appendResult` 必须使用数据库层原子操作（如 PostgreSQL `jsonb_insert` 或 `UPDATE ... SET data_json = jsonb_insert(...)`），避免两个任务同时完成时 `results` 丢失。
- 或使用乐观锁（版本号），写入前校验版本，版本不匹配时重新读取再写入。
- `selectResult` 同理，更新 `current_result_id` 时需保证不被并发覆盖。

### 18.4 资产来源协议

资产表 `assets` 需支持以下变更：

1. `assets.source_type` 新增来源类型：

| source_type | 含义 |
|---|---|
| `canvas_upload` | 用户在画布上传产生的资产 |
| `canvas_generation` | 画布节点生成产生的资产 |
| `canvas_export` | 画布合成/导出产生的资产 |
| `canvas_history` | 从节点历史结果保存到资产 |

2. 新增 `assets.source_ref` (text, nullable) 字段：

   - 用于存储 canvas_id 等文本类型来源 ID
   - 解决 `assets.source_id` (integer) 无法存储 canvas text ID 的类型不兼容问题
   - `source_ref` 存 canvas_id，`source_id` 留空
   - 需一次 migration 新增字段，成本极低

`assets.metadata_json` 中写入：

```ts
type CanvasAssetMetadata = {
  canvas_id: string
  canvas_title?: string
  node_id?: string
  node_def_id?: string
  run_id?: string
  task_id?: string
  result_id?: string
  action_label?: string
  prompt?: string
  references?: CanvasReference[]
}
```

写入规则：

- `assets.source_path = /canvas/{canvas_id}`。
- `assets.source_ref = canvas_id`（使用新增的 text 字段，不再需要放入 metadata_json）。
- `assets.source_id` 留空（canvas ID 是 text，不能塞入 integer 字段）。
- `assets.metadata_json.canvas_id` 必填。
- `assets.metadata_json.node_id` 在可定位节点时必填。
- `assets.task_id` 不绑定 `canvas_tasks`，因为类型不兼容。

#### 18.5.1 上传到画布

#### 18.5.6 升级业务动作接口

保留现有：

`POST /api/v1/canvases/:id/business-action`

扩展请求体：

```ts
type CanvasBusinessActionRequest = {
  action_label: string
  source_node_id?: string
  source_node_def_id?: string
  target_node_id?: string
  selected_node_ids?: string[]
  user_input?: string
  rendered_prompt?: string
  model?: string
  provider?: string
  aspect_ratio?: string
  style?: string
  duration?: number
  references?: CanvasReference[]
  output_mode?: 'backfill_source' | 'insert_new_node' | 'append_history'
  position_x?: number
  position_y?: number
}
```

兼容要求：

- 继续接受旧字段 `actionLabel / sourceNodeId / sourceNodeDefId / userInput`。
- 返回继续包含 `hidden_node_id / run_id / task_id`。

新增行为：

- `selected_node_ids` 存在时，后端从这些节点解析 references。
- `references` 显式传入时，和节点解析结果合并去重。
- `output_mode=insert_new_node` 时，生成结果作为新节点插入。
- `output_mode=backfill_source` 时，生成结果回填目标节点。
- 所有生成结果都必须写入目标节点 `results`。

`insert_new_node` 插入规则：

- 新节点的位置由前端在请求中传入 `position_x` / `position_y`，后端不负责计算视觉位置。
- 前端计算位置的策略：
  - 空白提示词生成：插入当前视野中心。
  - 单节点生成：插入来源节点右侧。
  - 多节点生成：插入选中节点组右侧。
- 新节点类型按结果类型映射为 `image / video-asset / audio / storyboard`。
- 新节点必须写入 `references`，记录来源节点或来源资产。
- 如当前画布展示连线，新节点可与来源节点建立轻量引用边；不要求进入复杂 DAG 编排。

#### 18.5.7 对话驱动接口（Skill 代理）

本接口是画布 AI 代理的核心入口。AI 拥有完整画布上下文，解析用户意图后调用 Skill 执行画布操作。

`POST /api/v1/canvases/:id/chat`

请求：

```ts
type CanvasChatRequest = {
  message: string
  selected_node_ids?: string[]
  canvas_context: CanvasChatContext
}

type CanvasChatContext = {
  node_count: number
  nodes_summary: Array<{
    id: string
    type: string
    label: string
    status?: string
  }>
  edge_count: number
  selected_node_ids: string[]
  recent_operations?: Array<{
    skill: string
    timestamp: string
    summary: string
  }>
}
```

响应（流式 SSE）：

```ts
type CanvasChatSSEEvent =
  | { type: 'text_delta'; content: string }
  | { type: 'skill_call'; skill: string; input: Record<string, unknown> }
  | { type: 'skill_result'; skill: string; output: Record<string, unknown> }
  | { type: 'plan_preview'; plan_id: string; operations: CanvasOperation[] }
  | { type: 'done' }
```

说明：

- `canvas_context` 由前端在每次请求时构建，包含当前画布图的摘要信息。
- AI 代理解析用户意图后，决定调用哪个 Skill。
- Skill 按确认要求分两级（与 §5.3 一致）：
  - **直接执行**：`create_nodes / add_to_context`——操作可逆或无副作用，结果通过 `skill_result` 事件返回。
  - **需确认**：`update_node / delete_nodes / create_edge / delete_edge / generate / save_to_assets`——操作修改现有数据或不可逆，先通过 `plan_preview` 事件展示操作计划，前端确认后调用 apply 执行。
- AI 可以在一次对话中调用多个 Skill（如"生成镜头并连线到合成节点"= create_nodes + create_edge）。
- 未开放 Skill 在对话中不可调用，AI 应回退为"请手动操作"提示。
- `0.23.0` 的 AI 代理解析层可以用确定性路由 + LLM 意图识别混合实现，不要求纯 LLM 驱动。

#### 18.5.8 应用操作计划

破坏性 Skill 和多步操作需要前端确认后执行。

`POST /api/v1/canvases/:id/chat/:planId/apply`

请求：

```ts
type ApplyCanvasChatPlanRequest = {
  operations: CanvasOperation[]
}
```

响应：

```ts
type ApplyCanvasChatPlanResponse = {
  canvas: CanvasDetail
  triggered_runs?: Array<{ run_id: string; task_id?: string }>
}
```

防护措施：

- plan 生成时对 `operations` 计算 HMAC 签名，随响应返回 `signature` 字段。
- apply 时前端必须同时提交 `signature`，后端验签通过后才执行。
- 签名密钥为服务端环境变量，前端不可见。

规则：

- 应用前再次校验 ownership。
- `create_node / update_node / create_edge` 进入同一个数据库事务。
- `trigger_action`（generate Skill 内部）在事务后触发，避免事务内启动长任务。
- 失败时不能产生半成品节点。

### 18.7 状态机

节点结果状态：

```text
none -> generating -> generated -> saved_to_asset
                 \-> failed
```

状态落点：

- `generating`：`useRuntimeStore` + `canvas_tasks.status=running`
- `generated`：节点 `results` 已有 url
- `saved_to_asset`：节点结果有 `asset_id`
- `failed`：`canvas_tasks.error_message` 不为空

对话代理状态：

```text
idle -> processing -> skill_calling -> skill_result -> idle
                   \-> plan_preview -> plan_applied -> idle
                                     \-> plan_rejected -> idle
                   \-> failed -> idle
```

状态落点：

- `processing`：AI 正在解析用户意图
- `skill_calling`：AI 调用了一个非破坏性 Skill
- `plan_preview`：AI 生成了破坏性 Skill 的操作计划，等待前端确认
- `plan_applied`：操作计划已执行
- `plan_rejected`：用户取消了操作计划
- `failed`：Skill 执行失败，画布状态不变

`0.23.0` 可不落表，plan_id 由后端生成后随响应返回，前端持有 operations。若后续需要审计，再新增 `canvas_chat_plans`。

### 18.12 开放问题

1. ~~`assets.source_id` 是 integer，无法保存 canvas text id；短期放入 `metadata_json.canvas_id`，长期是否新增 `source_ref` 字段？~~ **已决定**：0.23.0 新增 `assets.source_ref` (text) 字段，存 canvas_id。
2. 画布上传是否默认入资产？当前建议默认不入库，用户显式保存或上传时勾选。
3. 对话计划是否需要落表？当前建议不落表，等审计需求明确后再新增；若不落表，`planId` 只作为关联 ID，前端提交 operations 时需携带 HMAC 签名。
4. 多选是否支持框选？当前后续增强 A 只要求点选和已选节点动作，框选可后置。
5. 生成历史是否需要对象存储生命周期清理？当前先保留，后续配额系统再处理。
6. `data_json` 中 `results` 持续增长的性能问题：当前限制 20 条，如后续需要更多历史记录，是否迁移到独立的 `canvas_node_results` 表？当前建议 0.24.0 再评估。
7. AI 代理解析层用什么实现？`0.23.0` 可以用确定性路由 + LLM 意图识别混合。纯 LLM 驱动的成本和延迟是否可接受？需要原型验证。
8. `canvas.generate` Skill 与 `BusinessActionService` 的关系：Skill 是薄封装还是需要独立的生成编排？当前建议 Skill 薄封装 `BusinessActionService`，避免两套生成逻辑。
