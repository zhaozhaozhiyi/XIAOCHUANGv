# 0.23 规划评审定论

评审日期：`2026-07-06`
状态同步：`2026-07-08` 已确认 `0.23.2` 封版；本文保留 2026-07-06 的评审定论，当前版本事实以 [../VERSION_PLAN.md](../VERSION_PLAN.md) 与 [0.23.2封版说明.md](./0.23.2封版说明.md) 为准。
评审对象：

- `docs/0.23/短剧AI-first改编流程重构.md`
- `docs/0.23/0.23版本计划.md`
- `docs/0.23/待办评估清单.md`

评审视角：项目经理、产品经理、技术经理

## 1. 总定论

`0.23` 版本列车成立，且必须继续拆为 `0.23.1 / 0.23.2 / 0.23.3` 三个小版本推进。版本计划中“先修短剧主流程，再验收画布生产闭环”的原则是正确的，见 `docs/0.23/0.23版本计划.md:11` 到 `docs/0.23/0.23版本计划.md:18`。

`0.23.1` 的最终定论是：只交付短剧 AI-first 最小主链，不追求一次性完成所有理想页面和全量资产版本系统。它的核心不是页面重排，而是把用户看到的“假方案草稿”替换成真实 AI 产物链：源稿理解、改编策略、真实 Episode 蓝图、试播正文、单集工作台输入升级。

`0.23.2` 的最终定论是：画布不抢 `0.23.1` 主线，只做可信闭环验收。画布资产闭环、上传、生成历史、来源追溯和最小快速生成进入 `0.23.2`。

`0.23.3` 的最终定论是：只做画布 AI 对话与镜头体验增强。开放 `create_nodes / update_node / add_to_context` 三个最小 Skill，角色/场景端口连线和合成导出节点在可信闭环之后再收口。

必须消除一个口径冲突：`strategy` 能力不是可选，独立 `/strategy` 页面才是可选。`0.23.1` 必须让用户至少比较并选择 2 套 AI 改编策略，否则无法满足 `docs/0.23/0.23版本计划.md:105` 到 `docs/0.23/0.23版本计划.md:110` 的验收门禁；但研发容量不足时，策略能力可以先内嵌在概览页或分集页，不强制独立路由。

## 2. 项目经理视角

项目排期结论：`0.23.1` 只允许一条 P0 主线。所有研发、测试和评审资源优先投向短剧 AI-first。画布已部分落地的内容只能做保守修补和验收准备，不得成为 `0.23.1` 的交付焦点。

`0.23.1` 必做交付范围：

1. `/drama/[id]` 从混合工作区改成项目概览驾驶舱，删除“方案草稿”主面板。对应方案见 `docs/0.23/短剧AI-first改编流程重构.md:447` 到 `docs/0.23/短剧AI-first改编流程重构.md:478`。
2. 源稿导入后形成 `source_health / source_analysis`，用户能看到源稿健康与 AI 理解产物。
3. AI 生成 2 到 3 套 `adaptation_brief`，用户选择 `selected_brief` 后才进入蓝图。
4. 基于 `selected_brief` 创建真实 `Episode(status=blueprint)`，分集页只围绕真实 episode 工作。
5. 至少 1 集能从 blueprint 生成试播正文，并进入现有单集工作台。
6. 单集工作台能展示项目公共主档、单集引用/覆写、镜头私有产物的最小边界。

`0.23.1` 不做交付范围：

- 不做完整画布 Agent。
- 不做角色/场景画布端口连线。
- 不做合成导出节点收口。
- 不做完整资产版本系统。
- 不做独立角色圣经页、独立场景圣经页、独立原型页。
- 不强制独立 `/drama/[id]/settings`。
- 不把所有历史 `adaptationPlan` 一次性完整迁移完。

项目节奏建议：

1. 里程碑 A：数据与 API 最小闭环。新增或兼容 `source_analysis / adaptation_brief / episode.blueprint_payload / episode.source_trace`，能创建 blueprint episode。
2. 里程碑 B：项目前置主链 UI。完成概览、源稿、策略能力、分集蓝图和试播正文。
3. 里程碑 C：工作台接入。单集工作台读取 blueprint/script，并展示资产引用边界。
4. 里程碑 D：验收。补短剧 AI-first E2E，至少覆盖源稿、策略、蓝图、试播、工作台进入。

风险定论：

- 最大风险不是技术难点，而是范围膨胀。文档已经列出 `source / strategy / episodes / assets / settings` 五个子页，见 `docs/0.23/短剧AI-first改编流程重构.md:480` 到 `docs/0.23/短剧AI-first改编流程重构.md:620`。`0.23.1` 必须按“能力优先、独立页面后置”的原则收缩。
- 第二风险是迁移中断。当前代码仍大量使用 `adaptationPlan/方案草稿`，`待办评估清单` 已明确这一点，见 `docs/0.23/待办评估清单.md:58`。因此 `adaptationPlan` 应先作为兼容层，不作为用户主流程对象。
- 第三风险是测试证据不足。`DEBT-01` 必须进入 `0.23.1` 验收工作，见 `docs/0.23/待办评估清单.md:94`。

## 3. 产品经理视角

产品定论：`0.23.1` 的用户价值是“用户每前进一步，都能看到真实 AI 产物”，不是“短剧项目页看起来更完整”。

现有方案的问题判断成立。当前“方案草稿”被明确识别为规则模板，不是真实 AI 产物，见 `docs/0.23/短剧AI-first改编流程重构.md:42` 到 `docs/0.23/短剧AI-first改编流程重构.md:58`。这会让用户误以为已经完成了改编决策，实际只是进入了一个漂亮但不可信的预览。

产品主路径定死为：

`源稿导入 -> 源稿健康检查 -> AI 源稿理解 -> AI 改编策略比较 -> 选择策略 -> 生成真实分集蓝图 -> 生成试播 1 到 3 集正文 -> 进入单集工作台 -> 单集制作与导出`

默认批量策略定死为先试播，不默认整季一键全生成。方案中已经给出这个判断，见 `docs/0.23/短剧AI-first改编流程重构.md:802` 到 `docs/0.23/短剧AI-first改编流程重构.md:822`。

页面产品口径：

- `/drama/[id]` 是项目驾驶舱，只回答当前状态、下一步动作和阻塞风险。
- `/drama/[id]/source` 是 0.23.1 P0 页面或等价能力，必须承接源稿健康与 AI 理解。
- `/drama/[id]/strategy` 独立页面是 P1，但策略生成、比较、选择能力是 P0。
- `/drama/[id]/episodes` 是 P0 页面或等价能力，真实 episode blueprint 是这里的主对象。
- `/drama/[id]/assets` 是 P1 页面或等价能力，0.23.1 只做项目公共主档和缺失项最小治理。
- `/drama/[id]/settings` 独立页面后移，不阻塞 `0.23.1`。

交互定论：

- 主流程里只能出现一个最推荐的下一步 CTA。
- 用户修改目标参数后，不再自动“重算方案草稿”。策略和蓝图必须有明确的生成、重生、选择和确认动作。
- 分集列表不得展示无法生产的假分集行。
- 角色圣经、场景圣经在 `0.23.1` 中作为派生视图，不作为前置硬门槛。方案也已明确“不再要求一开始就先完整生成”，见 `docs/0.23/短剧AI-first改编流程重构.md:757` 到 `docs/0.23/短剧AI-first改编流程重构.md:762`。

## 4. 技术经理视角

技术定论：`0.23.1` 应采用兼容式重构，不做一次性大爆炸替换。

代码现状验证：

- 当前 `/drama/[id]` 仍在前端生成规则式方案草稿，`generateAdaptationPlan` 调用 `buildDraftAdaptationPlan`，见 `apps/web/src/app/(default)/drama/[id]/page.tsx:1287` 到 `apps/web/src/app/(default)/drama/[id]/page.tsx:1315`。
- 当前分集创建仍从 `adaptationPlan.episode_outlines` 批量创建 episode，并把 outline 拼成 `content`，见 `apps/web/src/app/(default)/drama/[id]/page.tsx:1317` 到 `apps/web/src/app/(default)/drama/[id]/page.tsx:1367`。
- 当前数据库 `episodes` 只有 `content / script_content / status` 等字段，没有 `blueprint_payload / source_trace`，见 `apps/backend/src/db/schema.ts:250` 到 `apps/backend/src/db/schema.ts:275`。
- 当前已有 `characters / episode_characters / scenes / episode_scenes / storyboards` 基础关系，见 `apps/backend/src/db/schema.ts:277` 到 `apps/backend/src/db/schema.ts:342`。
- 当前角色场景提取会同时维护主表和关联表，但仍是“提取后直接写库”的模式，见 `apps/backend/src/modules/ai/skill-handlers/extractor.handler.ts:18` 到 `apps/backend/src/modules/ai/skill-handlers/extractor.handler.ts:29`。
- 画布资产、上传、历史、对话相关服务和前端组件已经存在，待办清单的“已基本落地/部分落地”判断大体成立，见 `docs/0.23/待办评估清单.md:61` 到 `docs/0.23/待办评估清单.md:67`。

技术实施切片：

1. 数据层先做最小字段，不追求全量资产版本系统。优先补 `source_analysis`、`adaptation_brief`、`selected_brief_id`、`episode.blueprint_payload`、`episode.source_trace`。这些字段与方案建议一致，见 `docs/0.23/短剧AI-first改编流程重构.md:736` 到 `docs/0.23/短剧AI-first改编流程重构.md:746`。
2. `adaptationPlan` 改为兼容层。旧数据可以映射为 brief 和 episode blueprint，但不得继续作为用户主流程对象。方案也建议弱化为兼容层，见 `docs/0.23/短剧AI-first改编流程重构.md:748` 到 `docs/0.23/短剧AI-first改编流程重构.md:755`。
3. 资产模型先按行为约定落地：`characters` 全部视为项目公共主档，`episode_characters` 只做引用，`scenes.episode_id = null` 视为公共场景，非空视为单集局部场景。后续再补 `scope / override_payload / render_snapshot`。这个最小兼容法已经在方案中给出，见 `docs/0.23/短剧AI-first改编流程重构.md:791` 到 `docs/0.23/短剧AI-first改编流程重构.md:800`。
4. 单集工作台不重写生产链，只增加输入读取和资产边界提示。`use-workbench.ts` 的拆分属于前置工程债，但只拆必要部分，不借机重构全部工作台。
5. AI 调用要有真实落点。源稿理解、策略生成、蓝图生成、正文生成必须走真实 AI 或明确的 AI run 任务记录；纯参数保存和模板拼接不得伪装成 AI。责任边界见 `docs/0.23/短剧AI-first改编流程重构.md:824` 到 `docs/0.23/短剧AI-first改编流程重构.md:840`。

技术不做：

- 不把画布 AI Runtime 与短剧工作台强行统一。
- 不在 0.23.1 改完所有 canvas API。
- 不在 0.23.1 建完整资产快照版本系统。
- 不在 0.23.1 解决全部 API client 合并、env 收敛、对象存储 SDK 替换等治理项。

必须加的技术门禁：

- 新增短剧 AI-first API 或服务测试。
- 新增 `drama-ai-first-source.spec.ts`、`drama-ai-first-strategy.spec.ts`、`drama-ai-first-episodes.spec.ts`、`drama-ai-first-workbench.spec.ts` 中的最小可跑版本。
- 对 `blueprint -> script_ready -> open_workbench` 加回归测试。
- 对旧项目存在 `adaptationPlan` 的情况加兼容测试。

## 6. 0.23.1 封版门禁

`0.23.1` 只有满足下面 8 条，才能认为版本规划真正落地：

1. 项目详情主流程不再展示“方案草稿”主面板。
2. 源稿导入后能看到健康检查和 AI 理解结果。
3. 用户能生成、比较并选择至少 2 套 AI 改编策略。
4. 系统能基于选定策略创建真实 `Episode(status=blueprint)`。
5. 分集页围绕真实 episode blueprint 工作，不展示规则 outline。
6. 至少 1 集能从 blueprint 生成试播正文，状态进入 `script_ready` 或等价生产态。
7. 单集工作台能读取 `episode.blueprint + episode.script_content`，并展示公共主档、单集引用/覆写、镜头私有产物的最小边界。
8. 旧 `adaptationPlan` 项目不崩溃，有明确兼容或迁移路径。

最终一句话：`0.23.1` 不是“短剧模块全面重做”，而是“把假的前置规划链路替换成真实 AI 产物链路”。做到这一点，版本成立；做不到这一点，即使补了很多画布能力，也不能算 `0.23.1` 成功。
