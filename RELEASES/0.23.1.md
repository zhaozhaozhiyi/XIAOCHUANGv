# 小窗 XIAOCHUANG 0.23.1 发布说明

**版本**: `0.23.1`
**状态**: 已封版
**发布日期**: 2026-07-07
**上一版本**: `0.22.0`
**下一版本**: `0.23.2`

## 1. 版本定位

`0.23.1` 是短剧 AI-first 主流程修正版。

本版本的定论是：短剧项目不再把“方案草稿”作为主流程对象，而是改为真实 AI 产物链：

源稿理解 -> 改编策略 -> 分集蓝图 -> 试播正文 -> 单集工作台生产。

这里的“Agent”产品口径不再指外部远程 Agent 服务，而是指已配置文本 AI API 之上的任务化执行器。前端不直连模型，后端通过当前激活的文本 AI 配置完成生成、校验、入库和任务状态追踪。

## 2. 主要更新

### 2.1 产品流程

| 模块 | 更新 |
|------|------|
| 短剧详情页 | 新增 AI-first 主流程状态，展示源稿健康、源稿理解、改编策略、真实分集蓝图和试播正文进度 |
| 旧方案草稿 | 保留兼容提示，但不再作为 0.23.1 主流程产物 |
| 改编策略 | 支持生成 2-3 套策略并选择主策略，后续蓝图基于已选策略生成 |
| 分集蓝图 | 基于策略创建真实 `Episode(status=blueprint)`，分集列表不再只依赖本地 outline |
| 试播正文 | 支持批量生成前几集试播正文，也支持单集生成、重写和蓝图再生成 |
| 单集工作台 | 工作台读取 `episode.blueprint_payload` 与 `episode.script_content`，明确项目公共资产、单集覆写、镜头私有产物边界 |

### 2.2 后端能力

| 能力 | 更新 |
|------|------|
| 源稿存储 | 新增 `drama_sources` 与 `drama_source_chunks`，保存源稿、章节/分块、摘要和溯源信息 |
| 长篇处理 | 源稿健康检查会估算 token、章节数和分块模式；超过上下文上限时走分块理解 |
| AI 执行器 | 新增 `DramaAgentService` 与 `RemoteDramaAgentAdapter`，通过已配置文本 API 发起结构化生成 |
| 结构化校验 | 新增源稿分析、改编策略、分集蓝图、试播正文的 JSON 解析、字段别名兼容和 schema 校验 |
| 任务队列 | 新增 `drama_sources`、`drama_adaptation_briefs`、`drama_episode_blueprints`、`drama_pilot_scripts` 四类任务处理器 |
| 分集追踪 | `episodes` 新增蓝图 payload、source trace、生成模式、脚本 AI run 追踪与失败原因字段 |

### 2.3 前端与契约

| 能力 | 更新 |
|------|------|
| API 客户端 | 新增 AI-first 接口、任务轮询、分集蓝图/脚本生成接口封装 |
| 类型契约 | 新增 `SourceHealth`、`SourceAnalysis`、`AdaptationBrief`、`EpisodeBlueprintPayload` 与 `DramaAiFirstStage` |
| E2E | 新增 `drama-ai-first-flow.spec.ts`，覆盖源稿导入、策略生成、蓝图生成、试播正文和工作台入口 |
| 规划文档 | 新增 GitHub 可见的 `docs/VERSION_PLAN.md` 与 `docs/0.23/` 版本规划、评审定论、研发规格和参考 PRD |

## 4. 已知风险与后续计划

| 风险 | 等级 | 处理计划 |
|------|------|----------|
| 模型输出仍可能出现字段别名、数组包装或中文字段 | Medium | 已做常见别名归一化，0.23.2 继续补充失败样本回归 |
| 长篇小说超过模型上下文时需要分块理解，质量依赖分块摘要稳定性 | Medium | 0.23.2 增加长篇样本集与分块摘要质量检查 |
| E2E 真实模型回归成本较高 | Low | 保留真实 API 开关，默认用类型检查和后端单测，必要时专项跑真实链路 |
| 画布资产闭环未在 0.23.1 作为主线验收 | Medium | 进入 `0.23.2` 画布可信闭环验收版 |
